# OTA 升级示例（板1 / STM32F407ZE）

片上升级（IAP）示例：**Bootloader + App + PC 下发脚本** 三件套，数据传输用板子现成的
USART3（PB10/PB11）接 **ESP8266-01S**，走 AT 固件透传；升级帧直接复用工程自己的
`sys_frame` 协议（AA55…CRC16…55AA），协议模块一行没改。

> 分区方案、固件头、帧命令字全部写在 `OTA1/ota/ota_part.h` 里 —— **Boot 与 App 共用这一个头**，
> 不许哪边各自复述地址。下图与表里的地址都出自它，和「STM32 速查 · OTA 分区与标志位表」一致。

## 2. 分区（板1 = F407ZE，512KB Flash）

| 区 | 地址 | 扇区 / 大小 | 说明 |
|---|---|---|---|
| Bootloader | `0x08000000` | Sector 0，16KB | 复位入口。只做四件事：查 → 校验 → 搬运 → 跳转 |
| **App 运行区** | `0x08004000` | Sector 1~3，48KB | App 的链接地址（Keil IROM1）与跳转地址 |
| 下载区（新固件暂存） | `0x08010000` | Sector 4，64KB | App 收下的新固件先写这里，Boot 校验通过才搬运 |
| 预留 | `0x08020000`~`0x0805FFFF` | Sector 5~6 | 以后放字库 / 日志，别占 |
| 参数区 A / B | `0x08070000` / `0x08060000` | Sector 7 后半 / 前半 | **工程 sys_flash 正在用**，升级流程一律不碰 |

下载区布局：`[0..15] 固件头` + `[16..] 镜像本体`。

固件头（16 字节）：

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0 | 4 | 标识 `'O' 'T' 'A' '1'`（逐字节比，不看端序） |
| 4 | 4 | 镜像字节数（小端） |
| 8 | 2 | 整镜像 CRC16-MODBUS（小端） |
| 10 | 2 | 版本号（只给人看，小端） |
| 12 | 2 | 头前 12 字节的 CRC16（防止头本身被写坏） |
| 14 | 2 | 保留（写 0xFF） |

### 为什么这样就不会变砖

- **先写镜像、最后写头**：头没写下去之前，Boot 认为"没有待装固件"，绝不会动 App 区。
- **App 侧先在 RAM 里攒完整镜像、CRC 通过才动 Flash**：校验不过就一个字节都不碰 Flash；
  Flash 只能"1 改 0"，边收边写一旦丢帧/重传就会写出坏数据，本方案从设计上避开了。
- **Boot 搬运幂等**：搬完 App 区、回读复验通过，**才**把下载区头作废（只写 4 字节，不用擦 64KB）。
  搬运到一半掉电 → 下次上电头还在 → 完整重搬一遍。App 区永远是"完整的新程序"或"完整的旧程序"。
- **App 无效就停在 Boot 的救援态**：不会跳进半截程序乱跑。

## 3. 数据通路

```
PC(ota_send.py)  --TCP-->  ESP8266-01S  --透传-->  USART3(PB10/PB11)  --sys_frame-->  App
        ↑                        ↑
   固件 bin                 AT+CIPMODE=1 后是一条裸字节管道，
                           所以 OTA 帧原样就是工程那套协议帧
```

帧格式（与 `sys_frame.h` 完全相同，载荷上限 64 字节）：

```
AA 55 | CMD | LEN | DATA(≤64) | CRC16低 | CRC16高 | 55 AA
CRC16-MODBUS，范围 = CMD + LEN + DATA
```

OTA 命令字（`ota_part.h`）：

| CMD | 方向 | 载荷 |
|---|---|---|
| `0x10` BEGIN | PC→板 | `[版本 2B][镜像大小 4B]`（大端） |
| `0x11` DATA | PC→板 | `[偏移 4B][数据 56B]`（大端；56 是 4 的倍数，保证 Flash 写地址 4 字节对齐） |
| `0x12` END | PC→板 | `[整镜像 CRC16 2B]` |
| `0x13` STAT | 板→PC | `[状态码 1B][已收字节数 4B]` |
| `0x14` QUERY | PC→板 | 空（问一下板子状态，可选） |

节奏：**发一帧 DATA 等一条 STAT**。TCP 本身可靠，这样做主要是为了进度对齐与限流；
串口直连模式（无 TCP）时也靠它保证不丢帧。

## 4. 接线（板1 ↔ ESP8266-01S）

| ESP8266-01S | 板1 | 说明 |
|---|---|---|
| TXD | **PB11** | USART3_RX（工程 `sys_usart.h` 就写着 USART3 接 ESP8266） |
| RXD | **PB10** | USART3_TX |
| GND | GND | **必须共地** |
| VCC | 3.3V | 峰值电流 ≥300mA：电源脚并 **100µF 电解 + 100nF**，别用 3.3V 小电流口 |
| CH_PD(EN) | 3.3V（经 10k 上拉） | 不拉高模块不启动 |
| GPIO0 / GPIO2 | 悬空（上拉） | 保持正常启动模式 |

要点：

- 板的 USART3 是**跳线选通**的（见 `FWLIB/inc/sys_usart.h` 的串口分配表），先确认跳线接上；
- **老出厂 AT 固件波特率可能是 9600**：先用串口助手发 `AT` 确认；若不是 115200，
  改 `esp8266_at.c` 里的 `ESP_BAUD` 后重编；
- 台架调试（不接 WiFi）可以用 USB-TTL 直接接 PB11/PB10，用脚本的 `--serial COMx` 模式，
  **此时把 ESP8266 断开**，别让两个发送源打架。

## 5. 两个 Keil 工程怎么用

| | OTA1（App） | OTA1_Boot（Bootloader） |
|---|---|---|
| IROM1 | `0x08004000`，48KB（已改好） | `0x08000000`，16KB（已改好） |
| 源码 | 原有全部 + `ota/` 三个 .c（已加进工程） | 只有 `boot_main.c` / `ota_image.c` / `boot_flash.c` / `boot_uart.c` + 共享的 `ota_crc16.c` |
| 依赖 | FreeRTOS + 完整 SPL（RTE） | **不依赖 FreeRTOS / SPL**，只裸寄存器 + 设备头 |
| 体积 | 实测 Code 22.3KB + RO 1.9KB ≈ 24KB（上限 48KB） | 实测 Code 2.9KB + RO 0.7KB ≈ 3.6KB（上限 16KB） |

编译（命令行，与 OTA1 自带的 `build_keil.bat` 同一套）：

```
E:\k5_v5\UV4\UV4.exe -r "OTA\OTA1\标准模板.uvprojx"  -j0 -o "OTA\OTA1\build_verify.log"
E:\k5_v5\UV4\UV4.exe -r "OTA\OTA1_Boot\OTA1_Boot.uvprojx" -j0 -o "OTA\OTA1_Boot\build_verify.log"
```

日志里必须是 `0 Error(s), 0 Warning(s)`（当前实测就是）。

⚠ **一个机器相关的点**：Boot 工程刻意不带 RTE 组件（免得整套 SPL 被拖进来撑爆 16KB），
所以 `core_cm4.h` 是手写进 IncludePath 的绝对路径：

```
E:\k5_v5\ARM\PACK\ARM\CMSIS\5.0.1\CMSIS\Include
```

换电脑 / 换 Keil 包版本时，改这一条（或改成挂 RTE 的 CORE 组件）。

## 6. 生成 bin 并烧录

1. **生成 bin**（Keil：Options → User → After Build/Rebuild 勾 Run #1，填
   `fromelf --bin --output "..\app.bin" ".\Objects\标准模板.axf"`；也可命令行 fromelf）。
2. **烧录顺序**（J-Link / ST-Link 都行）：
   - Bootloader → `0x08000000`（`OTA1_Boot\Objects\OTA1_Boot.hex`）
   - App → `0x08004000`（`OTA1\Objects\标准模板.hex`）
   - 也可以两个 hex 一次烧（地址不重叠）。
3. 首次上电看 USART1（CH340 @115200）日志确认 App 跑起来了。

## 7. 升级操作

1. 填 `OTA1/ota/esp8266_cfg.h` 的 WiFi 名/密码、PC 的 IP（`ipconfig` 查）、端口；
2. 重编 App 并烧录，接好 ESP8266；板子上电后串口会看到 ESP8266 上链过程；
3. PC 上（先起监听再上电板子）：

```
python OTA\tools\ota_send.py --tcp-server 8899 --bin app.bin --ver 2
```

4. 脚本会打印 BEGIN → 每帧进度 → END；板子回 `ERASING` 后**要等几秒**（在擦 64KB 扇区），
   然后回 `DONE`，板子复位；Bootloader 搬运完才跳进新程序。

**台架模式（不用 WiFi）**：`python OTA\tools\ota_send.py --serial COM7 --bin app.bin`

### 预期日志

板子（USART1）——升级前一次：

```
================================
 OTA Bootloader (board1 / Sector 0)
================================
no pending firmware
jump to App (0x08004000) ...
```

App 收到固件时：

```
[App] connecting ESP8266 / server ...
  >> AT
  << OK
  ...
[ESP8266] transparent now: uart = raw byte pipe, OTA frames go on it
[OTA] BEGIN: receiving new firmware
[App] OTA progress 10%
...
[OTA] CRC ok, writing download area (ERASING ack first, then erase 64KB sector)
[OTA] image + header written; reboot lets the bootloader copy it
```

板子复位后（USART1）：

```
pending firmware: size=24516 ver=2 crc=0x1A2B
image CRC ok, copying to app region ...
copy done & verified; download header invalidated
jump to App (0x08004000) ...
```

> 串口日志是 **ASCII**：ARMCC v5 对字符串字面量里的中文报 `#870-D` 警告，本仓库要求 0 警告，
> 所以中文都写在注释与本文件里。`esp8266_cfg.h` 里也**只放 ASCII 占位符**，别在那儿填中文 WiFi 名
> （填了会出警告，要中文名就得自己加编译选项）。

## 8. 限制与注意（先读这几条）

| 项 | 说明 |
|---|---|
| 镜像上限 48KB | App 侧在 **RAM 里攒完整镜像**（占 48KB RAM，实测 ZI≈85KB，IRAM 128KB 够）。要支持更大镜像，得改成"边收边写 Flash + 用序号防重写"，复杂度上一个台阶 |
| 擦除期间会"停一下" | 擦 64KB 扇区是秒级，期间 CPU 取指被硬件挂起、串口中断也停 —— 所以协议规定**先回 ERASING 再擦**，上位机收到后要等；发送方 `--erase-grace` 默认 8 秒 |
| 看门狗 | 本示例**没开 IWDG**。要开的话超时必须 ≥8 秒，并在擦/写前后各喂一次（`sys_wdg.h` 的 `SYS_WDG_Feed`） |
| 参数区不能动 | 下载区（Sector 4）与 App 区（Sector 1~3）之外，**任何擦除都不要落在 `0x08060000` 及以上**（那是 `sys_flash` 的参数区，`sys_flash.h` 里明确约束"程序代码不得越过 0x08060000"） |
| 运行区不宽裕 | 48KB 里现在用了约 24KB；加功能前先看 `.map`，别不知不觉越界（越界 = 装不下新固件） |
| 中文 WiFi 名 | 宏里必须是 ASCII（见上） |
| 断线重连 | App 的 `vTaskEsp` 每 5 秒重试上链；透传态一旦被清就会重连 |
| AT 固件 | 按 ESP8266-01S **出厂 AT 固件**写（`AT/CWMODE/CWJAP/CIPMUX/CIPSTART/CIPMODE/CIPSEND`）；刷过自定义固件的模块要另配 |

## 9. 已验证到什么程度

- 两个 Keil 工程（App / Boot）**各编一遍：0 Error、0 Warning**（体积见上表）；
- **分区地址与上限真的生效**（这条是本次加复核工具时实测抓出来的坑）：两个工程的
  `.uvprojx` 里 `LDads` 的 `<umfTarg>` 必须为 `1`、OnChipMemories 的 `<Ro1Chk>` 必须为 `1`，
  否则 Keil **忽略** IROM1 / OCR_RVCT4 里的 ROM 设置，改按器件默认 ROM（`0x08000000`、512KB、无上限）
  去链接 —— 表现是 App 被错链到 `0x08000000`（正面盖掉 Boot），但**编译不报错**，
  只会变成"升级成功却没生效"。修前实测 App 的 `.map` 是 `LR_1 (Base 0x08000000)`、`.hex` 起始
  `0x08000000`；修后是 `LR_IROM1 (Base 0x08000000, Max 0x00004000)`（Boot）、
  `LR_IROM1 (Base 0x08004000, Max 0x0000C000)`（App）。这两个字段改完要**重新全量编译**才生效。
- `tools/ota_send.py` 的 **台架自测 5/5 通过**（不接硬件，用一个按 `ota_app.c` 同样规则应答的
  "假板子"跑完整条下发流程，含两个反例：整镜像 CRC 不符 → `CRCERR`；镜像超 48KB → `TOOBIG`）；
- CRC16 向量与工程一致：`CRC16("123456789") = 0x4B37`；
- **体积 / 头 / 落点**可随时复核：工具箱 →「检查」→「固件预算」（`firmware_budget.py`，自检 21/21）：
  `--map` 对体积与分区上限、`--hex` 判地址是否落在预期分区、`--bin` 算 CRC 并按 `ota_part.h`
  生成 16 字节头、留空则只做分区表自检。实测 App / Boot 的 map 与 hex 都通过。
- **未做**硬件在环（没有实物板子/ESP8266 在手时做不了），这一步要你在板子上按下节清单跑一遍。

### 9.1 上板验收清单（待你在实物上跑）

三条用例，按顺序做；每条都写明"怎么造、看什么、算过"：

| # | 用例 | 怎么造 | 看什么 | 算通过 |
|---|---|---|---|---|
| 1 | 擦除期间看门狗 | 打开 App 侧 IWDG（`SYS_WDG_Init(4000)`），下发一次完整升级 | 串口日志从 `ERASING` 到 `DONE` 的这段（约 8 秒）有没有中途复位 | 没复位、能等到 `DONE`，重启后 Boot 报搬运成功、新程序版本号变了 |
| 2 | ESP8266 断线重连 | 升级到一半把 ESP8266 断电 5 秒再上电 | 板子 `vTaskEsp` 是否 5 秒内重连、能否用 `--tcp-server` 重新下发 | 重连成功、重发一遍能升到 `DONE`（断的那次不留半个镜像：头没写完整就等同"没待装固件"） |
| 3 | 坏包 / 掉电回滚 | ① 用 `ota_send.py` 正常发完 END 后**立刻断电**（不等到 DONE）；② 手动改坏 `app.bin` 一个字节再发 | ① 重新上电后 App 是否仍是**旧版本**（旧程序完好）；② 板子应回 `CRCERR`、一个字节都没写进 Flash | 两种都**不砖**：App 区要么是完整的旧程序、要么是完整的新程序，没有中间态 |

补充：第 1 条也是 RTOS 检查器第 8 条规则（"看门狗 vs Flash 擦写"）盯的事 ——
擦除期间 CPU 取指被硬件挂起、SysTick 与串口都停，喂不了狗；超时设短了就会复位。

## 10. 改协议时要动哪几处

1. `OTA1/ota/ota_part.h`（分区 / 固件头 / 命令字 / 状态码 —— 单一事实来源）
2. 板子侧：`ota_app.c`（收帧处理）、需要时 `boot_*`（搬运逻辑）
3. `tools/ota_send.py`（同名字段与命令字）
4. 分区改了记得同步改 `标准模板.uvprojx`（App）与 `OTA1_Boot.uvprojx`（Boot）的 ROM 起止 ——
   并且确认 `<umfTarg>`、`<Ro1Chk>`、`<IROM>`、`<OCR_RVCT4>`、`<Cpu>` 五处都对得上
   （只改 IROM1 而不勾 IROM1，Keil 会当没改，见第 9 节）。改完**全量重编**，再用
   工具箱 →「固件预算」`--hex` 复核 .hex 起始地址。
