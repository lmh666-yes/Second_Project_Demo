### 阶段 1｜工程与串口打通

**这一阶段要交什么**：用 qmake 打开 SerialMonitor.pro，把 COM 口以 115200 8N1 打开，收到的字节先原样打成十六进制。

| 里程碑（每个动作） | 验收判据（怎么算过） | 完成 |
|---|---|---|
| 用 qmake 打开工程：SerialMonitor.pro 与三个 Qt 模块 | Qt Creator 底部「编译输出」0 error 0 warning 结束，build 目录里出现 SerialMonitor.exe；双击能弹出主窗口（左串口区、中曲线、右统计）。 | ☐ |
| 串口对象建起来：QSerialPort 与 readyRead 信号 | 连好板子（或用一个 USB 转串口短接 TX/RX 自发自收）后，日志区每秒多出若干行「收到 20 字节：AA 55 01 0C …」。 | ☐ |
| 刷新端口列表：QSerialPortInfo 与 CH340 驱动 | 插上板子前点刷新是「发现 0 个」+ 提示驱动；插上后（设备管理器能看到 USB-SERIAL CH340）再点刷新，下拉框里出现 COM 号。 | ☐ |
| 打开串口：115200 8N1，且必须 ReadWrite | 下拉框里选中 COM 号 → 点「打开串口」：按钮变「关闭串口」，日志区出现「已打开 COMx @ 115200 8N1（双向）」，随后每秒刷出十六进制帧。 | ☐ |

### 阶段 2｜协议解析与数据模型

**这一阶段要交什么**：把字节流变成 6 路环境值：20 字节帧、CRC16-MODBUS、状态机收帧与重同步，最后接进 DataModel。

| 里程碑（每个动作） | 验收判据（怎么算过） | 完成 |
|---|---|---|
| 帧长这样：AA 55 \| CMD \| LEN \| DATA \| CRC \| 55 AA | 你拿板子实际发出的 20 字节，能逐段念出：帧头 AA55、CMD 01、LEN 0C、温度大端 0x0988 = 2440 → 24.40 ℃、CRC 低字节在前、帧尾 55AA。 | ☐ |
| CRC16-MODBUS：init 0xFFFF、poly 0xA001 | 用 --selftest 的「组帧回环」用例自证：buildEnv() 组出的帧再解析回来，数值与输入逐位相同；报告里该条 PASS。 | ☐ |
| 收帧状态机：帧头 + 长度 + CRC 三重确认 | 串口开着时，界面曲线每来一帧就多一个点；且日志区不出现「CRC 错：累计 N」「帧尾错：累计 N」「长度字段非法：累计 N」这三种行。 | ☐ |
| 重同步：校验失败只丢 1 字节，不丢整帧 | 用 --selftest 的「三帧粘包（接缝 55 AA AA 55，60 字节）」与「半帧残段 + 噪声 → 重同步」两条用例验收：两条都 PASS，且解析出的帧数是 3 与 1。 | ☐ |
| 按字节分包也要能收：一个帧可能分 20 次到 | --selftest 的「逐字节分包（20 次 feed）」与「半帧残段 + 噪声 → 重同步」用例 PASS；现场日志不出现「长度字段非法：累计 N」。 | ☐ |
| 解析成 6 路环境值：接口是 EnvFrame::unpack | --selftest 的「负温度（0xFE0C → -5.00℃）」与「湿度无效标记（humiX100 = -1 → 界面显示 --）」两条 PASS。 | ☐ |
| 接进数据模型：DataModel 存什么、怎么取 | 喂几帧演示数据后，右侧统计区的「点数」「最大」「最小」跟着涨；曲线出现 6 条点位（一次只显示一条，其余靠图例切换）。 | ☐ |

**本阶段完成判定**：本阶段的产物：① 一个与板1 组帧严格对应的解析器（帧头 + 长度 + CRC 三重确认，错帧丢 1 字节重找）；② CRC16-MODBUS 实现（init 0xFFFF / poly 0xA001），与板1 的期望字节逐字节一致；③ 一个数据模型：6 条曲线数据、统计值、序号横坐标；④ --selftest 的 18 个用例全过，其中真正难的是粘包与重同步。

| --rangecheck：物理量边界，5 个用例 | 量程校验自检.txt 里 5 条全 PASS，末行「结论：边界处理符合预期」，退出码 0。 | ☐ |
