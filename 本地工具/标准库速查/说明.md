## 用法

### 📖 资料查询板块

- **搜索框**：中文、英文、**中英混排**都能搜，**不加空格也行**——
  - **自动分词**：`打开DMA中断` 会切成 `打开` + `DMA` + `中断`（中英文交界处切开、中文再按最大匹配分词），
    命中的是 `DMA_ITConfig`（它就是把 DMA 中断打开的那个函数）；
  - 也可以照旧空格分词：`串口 中断` / `看门狗 喂狗` / `ADC 采集`；函数名（`USART_Init`）、宏名（`GPIO_Mode_OUT`）直接敲；
  - **相关性排序（idf 加权）**：越少见的词权重越高——`dma` 重，`it` / `init` 这种到处都出现的词几乎不计分，
    所以不会一搜就几百条噪声（改前搜「打开DMA中断」首位是 `NVIC_EnableIRQ`，现在是 `DMA_ITConfig`）；
  - **名字按词边界匹配**：`DMA_ITConfig` 里的 `IT` 能被「中断」命中，`Init` 里的 `it` 不会被误当成中断；
  - **中文同义词自动展开**：搜「初始化」会同时匹配 `Init` 系列函数；搜「看门狗」匹配 `IWDG`/`WWDG`；
    搜「占空比」匹配 `SetCompare`/`Pulse`；搜「喂狗」匹配 `ReloadCounter`；
  - **错别字 + 英文拼写容错**：`初使化`→初始化、`中段`→中断、`定时期`→定时器；英文拼错一个字母也能纠正
    （`usrat`→`usart`、`iic`→`i2c`、`irq`→`irqn`/`handler`）；
  - **动作词只影响排序、不卡结果**：`打开`/`配置`/`初始化`/`设置` 这类词不当作必命中条件——
    「打开DMA中断」= 找 DMA 中断，正文里写了"使能 / 打开"的排前面；
  - **组合词识别**：`读取状态`、`设置优先级`、`初始化定时器` 这类没空格的复合词也能命中；
  - **概念词也能拆**：`空闲中断`（→ idle/rxne）、`采集`（→ adc/sample/dma）、`外部中断`、`中断线` 等已收录，
    多词查询时每个词都可以用它的英文同义词去命中（`ADC 采集`、`FLASH 扇区`、`I2C 从机` 都能查到）；
  - 结果太少时页面会提示：试试更短的词，或直接写中文功能词（如 `打开DMA中断` / `串口 中断`）。
- **左侧列表**：**点模块后按「结构体 → 初始化 → 使能/启动 → 功能函数」排序**；每项两个徽章——`模块` + `类型`：
  - 紫色 **详解** = 精写的用途 / 参数 / 返回值 / 示例（手写条目）;
  - 灰色 **原型** = 自动收录（ST 官方头文件原始声明 + **中文参数解释 + 返回值说明**，见下）;
  - **结构体** = 配置结构体逐字段解释；**芯片对照** = ZE/ZG 差异表；**查找表** = 中断向量表（带处理函数名）/ 时钟使能表 / 复用功能表 / FLASH 扇区表 / DMA 映射表 / 中断宏表 / 标志宏表 / EXTI 线表 / NVIC 分组表 / RTC 唤醒时钟表 / 结构体成员表 / 外设引脚映射表 / 定时器通道表 / ADC 通道表 / 时钟树表 / 器件 I2C 地址表 / FreeRTOS 配置宏表 / 常用计算公式表 / USART 波特率表 / SPI 分频表 / I2C 速率表 / CAN 波特率表 / 看门狗配置表 / 存储映射与位带表 / W25Q128 指令表 / 中断优先级分配表 / 传感器寄存器与换算表 / 两板外设驱动一览表；
- **右侧详情**：用途 / 原型 / **参数说明（参数名 + 可选值 + 中文解释"这个参数是什么"）** / **返回值说明** / 调用示例（可一键复制）；
- **「本项目使用位置」段**：自动扫描你四个工程组的源码，列出该函数在你**自己代码**里的调用位置。
  每条显示「工程标签 + 相对路径:行号 + 调用/定义/声明」——**绿色标签是本项目两个工程（S1检测端 / S2网关），优先收录**，灰褐色是参考工程（天马库 / 04ST32）。
  「调用」= 这里真的调用了这个函数（最有用）；「定义」= 这个函数在本文件里实现；「声明」= 只是头文件原型。
  由 `gen_usage.py` 扫描生成（记录格式 `{tag, f, l, p}`，同一工程保底占名额，行号与源文件严格对齐，可去 IDE 核对）；
- **「相关与联动」段**：配套函数链一览（谁先谁后、缺哪个不行），条目名可点击直接跳转；
- 顶部下拉框按模块筛选。
- **本板块只放"资料"**：初始化流程卡与引导向导**不在这个板块**（已全部移到「📚 引导教程」）。
  如果你在资料板块搜的其实是教程内容，列表顶部会出现一条
  **「📚 引导教程里有 N 个相关教程 —— 点这里切过去看」**，点一下即带着当前关键词切到引导教程板块。

> **自动条目的参数与返回值是怎么补全的**（`data_doc.js`，由 `gen_doc.py` 生成）：
> 从 Keil DFP 的 SPL 源码里提取权威签名 + Doxygen `@param`/`@retval` 官方注释，
> 再用 **549 条参数名中文字典** 翻译。当前覆盖 **718 个函数 / 1109 个参数**：
> · **1109/1109 = 100% 的参数都有明确中文解释**（说明"这个参数是什么、为什么要它"，而不是只给可选值）；
> · **718/718 个函数都有返回值说明**（按返回类型给出标准取值，如 FLASH_Status 列出
>   COMPLETE / BUSY / WRP / PROGRAM / TIMEOUT 各自含义）。
>
> 这些说明同时**并入搜索语料**，所以按参数含义也能搜到函数（例如搜「占空比」能命中 `TIM_SetCompare1`）。

### 🧭 项目引导板块

点顶部「🧭 项目引导」进入，右上角下拉框切换工程（**板1 检测端 / 板2 数据通信端 / Qt 上位机**）。
它不是"我替你写好的代码"，而是**你自己从头设计时用的阶段清单**：每个阶段 = 一串动作，每个动作只讲四件事 ——

- **为什么要这一步**（不做会怎样）；
- **这一步做什么**（具体到文件与函数）；
- **用哪个真实 API**（只写两板 FWLIB 里真实存在的函数名，能在「📖 资料查询」里搜到完整签名）；
- **怎么验证这一步成功**（必须能看见现象：LED / 串口打印 / 蜂鸣器 / 示波器 / 逻辑分析仪）+ **坑**。

规矩：**界面（板1 OLED、板2 TFT、Qt UI）由 AI 完成**，你负责 main.c、任务划分、数据与协议处理。
三个工程各自有一份进度文档（`板1进度文档.md` / `板2进度文档.md` / `QT上位机进度文档.md`），**只由你自己写**。

## 特色条目（续）：传感器数据手册卡

**流程卡解决"怎么用 I2C 读一个从机寄存器"，数据手册卡解决"这颗芯片的地址是多少、先发哪个命令字、读回几个字节、怎么换算成物理量"。**
这一类内容原先散落在流程卡和驱动笔记里，翻起来要来回找，所以单独成卡（青色「数据手册」徽章）：

| 卡片 | 内容 |
|---|---|
| SHT30 温湿度 | 测量命令字（0x2400 / 0x2C06 单次测量、**0x30A2 是软复位、0x2130 才是每秒周期测量**）、6 字节返回怎么切、温度 `-45+175*raw/65535` 与湿度 `100*raw/65535` 换算、CRC 字节不是数据 |
| BMP280 气压 | 寄存器图（0xD0 验货 / 0xF4 CTRL_MEAS / 0xF5 CONFIG / 0xF7 数据 / 0x88 校准系数）、**必须先读校准系数**、CTRL_MEAS = `(osrs_t<<5)|(osrs_p<<2)|mode`（驱动默认 0x4D 强制单次）、温度与气压的补偿顺序不能反、为何气压只能 ×10 |
| BH1750 光照 | 上电 0x01 + 模式 0x10、连续模式下读 2 字节不用先发命令、**lux = 原始值 ÷ 1.2（直接当 lux 会大 20%）**、0xFFFF 是过饱和、MTreg 出厂 69（31~254 可改量程）、ADDR 接高变 0x5C |
| CCS811 空气质量 | **WAKE 脚不拉低就连地址都扫不到**、HW_ID 必须 0x81、必须发 APP_START(0xF4)、**STATUS = bit4 APP_VALID / bit3 DATA_READY / bit0 ERROR**、48 小时老化、基线存 Flash |
| MQ-135 空气质量（模拟） | 5 V 供电、**AO 可能接近 5 V，必须分压到 ≤ 3.3 V**、预热 ≥48 小时（手册表1/表2：贮存 1~6 月要 ≥72 h、>6 月要 ≥168 h；24 h 是 MQ-2 的值）、`Rs=(VCC−Vout)/Vout×RL`、不标定 R0 就不给 ppm（帧里发原始 ADC） |
| DHT11 温湿度（单总线） | 主机拉低 ≥ 18 ms 起始、40 位数据 + 校验和、采样间隔 ≥ 1 s、读的时候要关中断（时序靠 µs 级延时） |
| AHT10 温湿度 | 地址 0x38：0xE1 0x08 0x00 校准 → 0xAC 0x33 0x00 触发 → 读 6 字节；`RH=h×100/2^20`、`T=t×200/2^20−50` |
| 光敏电阻 + ADC（辅助） | 与 BH1750 对照：ADC3_IN5 / PF7 分压采样、`R_photo=R×(3.3−Vout)/Vout`、不标定只能给相对值 |
| 传感器总线与地址总表 | 本项目 I2C 地址零冲突核对表（含 AHT10 0x38 与模拟通道）+ 上拉电阻/共地/杜邦线长度/I2C 互斥锁 + `SYS_I2C_Scan()` 验收法 |

每张卡都是「器件说明 → 寄存器/命令表 → 初始化与换算代码 → 常见问题与结论」四段，表头按内容自定列数。

## 写数据时的引号规则

- JS 字符串**内部**不要裸写半角引号 `"`：
  - 中文说明里的引号用**全角** `“ ”`（如 `存“首次初始化标志”`）；
  - 代码示例字段 `e` 里要显示半角引号时，必须写 **`\"`**（转义），如 `e:"xTimerCreate(\"T1\", ...)"`；
- 写错会让整个文件静默失效（页面少一半数据，控制台报 SyntaxError）——
  改完数据后先刷新页面确认条数正常，再跑核验脚本。
