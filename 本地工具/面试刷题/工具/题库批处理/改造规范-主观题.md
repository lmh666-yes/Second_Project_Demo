# 主观题内容改造规范（v1，严格执行）

## 背景与目标
文件 `D:\github\面试刷题\面试题刷题软件-主观题\题库\02_主观题.md` 中每道题的「**参考答案：**」段需要改造为两段：
- `**题目解析：**` —— 解析：讲清原理、依据、推导、示例、易错点、延伸考点
- `**标准答案：**` —— 标准答案：精简、完整、可直接作为考试作答的答案
「**得分点：**」段保持原样一字不改；题干、其它题、标题一律不动。

## 硬性格式
改造后每题结构：
```
**N.** 题干……（原样保留）

**题目解析：** <解析正文>
**标准答案：** <标准答案正文>
**得分点：** <原文，不动>
```
- 替换范围：从 `**参考答案：**`（或 `**参考译文：**`）这一行开始，直到 `**得分点：**` 之前的全部内容（含原答案正文所有行）。
- 新写入的两行不得包含会干扰解析器的符号：行首 `#`、`---`、`**`、```（正文行内的 `` ` `` 反引号可保留用于行内代码）。
- 不要改动任何 `**数字.**` 题干行，不要碰其它题。

## 内容质量标准（关键！）
1. **完整**：原文的所有技术信息（结论、推导、公式、示例、注意事项、易错提醒、延伸考点）必须保留——全部吸收进「题目解析」或「标准答案」，不得省略、不得弱化。
2. **准确**：不得改变任何技术结论、代码、数字、术语；不得编造原文没有的事实。原文笔误可纠正，但不得引入新主张。
3. **标准答案**：精炼的考试作答——直接给出答案与关键依据（1~6 句；数值/计算出题给结果与关键步骤；“写输出结果”题给输出结果+一句理由；英译题给完整译文）。要求单独拿出来就能看懂、能得分。
4. **题目解析**：展开讲解——为什么、原理/机理、示例、边界情况、易错点、延伸考点。行文通顺；不要只是复制标准答案的句子。
5. **风格**：专业、紧凑、直给结论；可用 `` `反引号` `` 标注代码/关键字；可用 ①②③ 分点。**每段写成一个长句段落（单行），不要换行**，与原文件风格一致。

## 工作流（每批）
1. 读 `02_主观题.md` 中分配题号的原文（grep 定位 `**N.**`，读取整块）。
2. 写数据文件 `D:\github\面试刷题\工具\题库批处理\batch_XX_data.py`（UTF-8，不带 BOM）：
   ```python
   # -*- coding: utf-8 -*-
   NEW = {
       27: ("……题目解析全文……", "……标准答案全文……"),
       # ……
   }
   ```
   每条为**单行长字符串**，用英文双引号包裹；中文引号“”无需转义；正文若含英文双引号用 \" 转义。
3. 运行：`python D:\github\面试刷题\工具\题库批处理\apply_batch.py D:\github\面试刷题\工具\题库批处理\batch_XX_data.py`
   - 预期输出「成功改造 N 题: [...]」，题号与分配完全一致；有「失败」必须修正后重跑（失败时脚本不会写坏文件）。
4. 自检：`cd D:\github\面试刷题\面试题刷题软件-主观题` → `python core\build_bank.py` → 应输出 449 题、无新告警。
5. 报告：本批题号、特殊处理说明（如原文极短、含代码块、参考译文等）。

## 样板
md 中 **#1**（volatile）与 **#3**（GET/POST+Cookie）已按规范改造完成，可直接打开对照风格（题目解析 = 原理/示例/易错；标准答案 = 直接作答）。

## 特殊情况
- 原标是 `**参考译文：**` 的英译题：标准答案 = 完整译文；题目解析 = 术语对照/翻译要点。
- 题块内有 ``` 代码块：代码原样保留在「标准答案」里；「题目解析」解释代码要点。
- 题目原文本身很短的（一两句）：允许解析较短，但原文信息仍必须全部保住。
- 若在文件中遇到 `**368b（续题号见上文）.**` 这类非标准行：跳过，不要动。
