## 二、题库规范

### 2.1 三类题库的分界（判据）

| 归到哪 | 判据（按**作答方式**分，不按题目难度） | 例 |
|---|---|---|
| **01 客观题**（自动判分） | 有唯一答案、可选项化：单选 / 多选 / 判断 | "下列…正确的是（ ）"、"…说法是否正确" |
| **02 主观题**（打字对照） | 需要**打字写出**：填空、简答、概念解释、计算、**写出程序输出结果**、指出错误、代码/文字分析 | "写出输出结果"、"简述…区别"、"为什么" |
| **03 编程画图大题** | 需要**编写完整函数/程序/宏/Makefile/脚本**，或**画图/看图分析**（电路、波形、时序、逻辑图） | "请实现…函数"、"画时序图"、"补全代码" |

边界细则（易争议的一律这样处理）：
- "写出输出结果 / 找错 / 补全一行" → **主观题**
- "写一段能跑的代码（函数/程序/宏/构建脚本）" → **大题**
- "写出 if 语句 / 定义宏" → **大题**（属写代码）
- "解释一段代码的含义（不写代码）" → **主观题**
- "看图回答电平/波形/参数" → **大题**（看图分析）

### 2.2 字段格式（解析器严格匹配，写错=题目缺答案）

**01 客观题**（`core/bank_parser_md.py`）：
```
**214.** 题干（可含 ``` 代码块）

- A. 选项一
- B. 选项二

**答案：D**
**解析：** 考点定位 + 正确项依据 + 干扰项分析 + 易错提醒
**来源：** <素材名> 第 N 题

---
```
- 多选写 `**答案：BC**`；判断写 `**答案：✅ 对**` / `**答案：❌ 错**`；存疑题写 `**答案：存疑…**`（软件显示为"特殊题"）
- 选项行必须是 `- A. xxx`（A–E、大小写、`)、、` 等分隔符都兼容）

**02 主观题 / 03 大题**（`core/bank_parser_md.py`，2026-10-05 新格式）：
```
**400.** 题干

**题目解析：** 机理/推导/示例/易错点（完整、科学、真实；合并说明等出处注记放這裡或末尾）
**标准答案：** 考试大题式精简答案（代码题附**完整可编译代码**）
**得分点：** ①… ②… ③… ④加分：…（每条都要能逐条打分，禁止「两种方法任一。」这类题面复读；入库前扫描 < 12 字的得分点，见 5.11）
**热点：** 是   ← 只给高频题加；没有这行就是非热点
**来源：** <素材名> 第 N 题

---
```
- 旧字段 `**参考答案：**` **仍兼容**（作为标准答案兜底，已全量迁移，不推荐新题再用）
- 显示顺序：**手机端 `✅ 标准答案` → `📖 题目解析` → `📝 自评要点`（答案优先，2026-10-13 起）**；桌面端仍为 `📖 题目解析` → `✅ 标准答案` → `📝 自评要点`。三块用绿/蓝/紫卡片区分，代码自动渲染成等宽代码块（见 5.11）
- 正文**禁写 `**`**（解析器会剔掉，C 二级指针写成 `int * *p`）；代码必须放 ``` 围栏

> ⚠️ **字段行必须一字不差**：`**参考答案：**`、`**得分点：**`、`**解析：**`、`**来源：**`。
> 写成 `**参考答案（说明）：**` 会导致**导入后答案是空的**（已踩坑）。

### 2.3 编号规则
- **只在末尾追加**，不重排已有编号（`progress.json` 按 `id` 记进度，重排会丢用户进度）
- ⚠️ **追加前先看“最大编号”而不是“题目总数”**：题库编号常有空档（迁出/合并留空），如主观题曾有 449 道题但最大编号已到 491 —— 新题编号要接**最大编号 + 1** 起（否则会撞号，导致考试抽题重复、进度串题）
- 去重合并后**允许留空号**，但在文件末尾"附：统计"里写明哪些号空了、为什么
- 大题第一部分沿用主观题老编号（6、7、8…），第二部分 401~480，第三部分从 481 起，第四部分 496 起；**新增一律往后接**

### 2.4 配图规范
- 图片放在 `imgs/`，md 里写 **本地相对路径**：`[图](../imgs/xxx.png)`（相对 `题库/` 目录）
- 不要引用素材目录（`面试刷题/素材/…`）里的原图（删素材后会导致图片丢失）
- 需要增强清晰度时用 `面试题刷题软件-*/tools_prepare_imgs.py`（灰度+对比+2 倍放大+锐化；默认不裁切，`--crop` 才裁，`--restore` 还原）
- 原卷手写作答痕迹要打码（避免泄露答案）

### 2.5 内容质量要求
- **客观题解析**：四段式 —— 考点定位 → 正确项依据 → 干扰项分析（逐个错项为什么错）→ 易错提醒/拓展
- **主观/大题答案（2026-10-05 起）**：拆两段——`题目解析`（机理/推导/易错，完整保留知识点）+ `标准答案`（精简到“一道考试大题”的体量；代码题附完整代码+关键注释）；`得分点`保留在最后供自评
- **大题答案**：可运行代码 + 要点说明 + 得分点；画图题给"图面要点 + 参考描述"
- **原卷明显错误**（题目错字、标答错）要**改正并在解析里说明**（例：`int (*p)[3]` 原标 C → 更正 D）
- 忠于原卷：原卷的代码错误可保留并注明"按修正后作答"

### 2.6 去重规则
1. **同一题在多份试卷出现** → 合并到最先收录的那条（保留原编号），在保留题的**来源行/得分点末尾**写"同第 X 题（<素材名>），重复题已合并"
2. **同题变体**（改数值、换打印顺序、换语言）→ **保留**，并在得分点末尾互相标注"变体：第 X 题（差异说明）"
3. **空壳题**（`**参考答案：** 同第 X 题`）→ 合并进目标题，删掉空壳
4. 合并前先用 4-gram/题干相似度全库扫一遍（客观 ≥0.84、主观 ≥0.62 需人工确认）

## 三、标准流程（SOP —— 每次加新素材照做）

**第 0 步 · 读要求**：先读本文件（尤其二、三、六节）。

**第 1 步 · 识别素材**
1. 用 `python 面试刷题\工具\素材识别\素材识别.py <素材目录>` 生成 `_识别结果.md`（图片走 Windows OCR：`面试刷题/工具/素材识别/ocr_win.ps1`；PDF 走 pymupdf；docx 走 python-docx）
2. **OCR 只当索引，正文以原图为准**：我会逐张看图核对（代码、下划线、下标、数学符号 OCR 基本会错乱）
3. 记下每份素材的"试卷名 + 题号 + 分值 + 难度标记"，便于写"来源"行

**第 2 步 · 分类**：按 2.1 的判据把每道题分到 客观 / 主观 / 大题（拿不准的列出来问你）。

**第 3 步 · 编写**
- 写答案与解析/得分点（按 2.5）；
- 原卷有问题就改正并说明；
- 需要配图的题目：从素材里裁出配图 → 存 `imgs/` → md 里写本地链接。

**第 4 步 · 编号与合并**
- 客观题接当前最大号往下排；主观题接最大号；大题从 481 往后接；
- 全库查重（2.6），该合并的合并、该标注的标注。

**第 5 步 · 重建题库**
```powershell
cd 面试题刷题软件-客观题 ; python core\build_bank.py      # 看题数统计与告警
cd 面试题刷题软件-主观题 ; python core\build_bank.py
```

**第 6 步 · 自检（必做）**
- 客观：`python tests\smoke_interview.py`、`test_brust.py`、`test_ui_long.py`
- 主观：`python tests\smoke_subjective.py`、`test_exam_cover.py`
- 测试里写死的题量期望要同步更新
- 全库格式检查：答案行/解析行/得分点行齐全、图片引用都存在、编号无重号

**第 7 步 · 打包**
```powershell
cd 面试题手机版-客观题 ; python build_web.py     # 生成 www/index.html + 根目录 .html + assets
cd 面试题手机版-主观题 ; python build_web.py
# 重建 APK（JDK17 + Android SDK 已配好）
$env:JAVA_HOME='D:\dev-tools\jdk-17.0.20.1+1'
$env:ANDROID_HOME="$env:LOCALAPPDATA\Android\Sdk"; $env:ANDROID_SDK_ROOT=$env:ANDROID_HOME
& <项目>\android\gradlew.bat -p <项目>\android assembleDebug --console=plain *> 日志
Copy-Item ...\app-debug.apk <项目>\面试刷题-X.apk -Force
```
- 校验：解包 APK 里的 `assets/index.html`，确认题量与新题存在
- 英语刷词改动时：`python build_web.py` + `gradlew assembleRelease`（签名 apk）

**第 8 步 · 更新文档**：各 README 的题量/结构/更新记录；题库 md 末尾"附：统计"（题量、编号空档、去重说明）。

**第 9 步 · 提交**：`git add` 相关目录 → `git commit`（写清题量与改动）→ `git push origin main`。
> 素材目录（`面试刷题/素材/` 下的 `面试题md/`、`高薪工作面试题图片/`、`附加面试题/`、`附加面试题2.0/`）**不入库**（已加 `.gitignore`）；工作区的临时文件（`_audit*.md`、`_识别结果.md`）用完即删；题库批处理工具在 `面试刷题/工具/题库批处理/`。

**第 10 步 · 汇报**：给出"新增 X 题 / 都归到哪 / 关键修正 / 测试与打包结果 / 下一步可选项"的简报。

## 五、功能规则（v1.2 新增）

### 5.1 错题/错词【寿命机制】（客观题三端 + 英语手机版；2026-09-22 起生效）

> 旧规则（“顺序/考试答对即移出错题库”）**已废弃**。现在错题只能靠“错题考试”答对清零。

1. **答错（任何模块：顺序 / 错题重做 / 普通考试 / 错题考试）**：题入错题本、累计错误次数 `wrong_count` +1（**永久记录**，只增不减）。
2. **入集时寿命 `life` = 1**（若曾被清零移除、之后又答错，重新入集并重新从 1 起算；累计次数继续累加不清零）。
3. **阈值加寿命**：`wrong_count` 为 **3、5、7、9** 时各 +1（3→+1、5→+1、7→+1、9→+1）；**超过 10 后每错一次 +1**（第 10 次不加，>10 即 11 次起每次都加）。
4. **只有「错题/错词考试」答对**才 `life -1`；**顺序/普通考试答对不清除错题**（只更新对错状态）。
5. **`life` 归零 → 移出错题本**；成绩页提示“本次清除 N 道 / 剩余 N 道”。
6. **错题考试答错**：寿命不扣；但若本次错后累计次数恰达/超过阈值，仍按第 3 条 +1（这是“错误次数达阈值各+1”的全局解读，如与预期不符可在此处调整）。
7. 进度字段：每题 `{ok, wrong_count, in_wrong, life, notes}`；旧进度自动迁移（按旧 `ok===false` 推导一次错题集）；统计栏“错题 N”按 `in_wrong` 计数。

### 5.2 错题考试 / 错词考试
- **入口**：错题板块底部按钮「📝 错题考试」（英语：“📝 错词考试”）。
- **抽题**：从错题本**随机抽 ≤10 道**（不满 10 道也可开考）；英语为**给英文选中文**选择题。
- **规则同模拟考试**：选项随机（答案跟随内容）、可暂停/退出/恢复、交卷后成绩页 + 题号导航 + 逐题回顾。
- 考试次数单独统计（`_wexam_count`）；**完成交卷才计入次数**。

### 5.3 收藏题目（主观题桌面 + 手机，v1.2 新增）
- 「⭐ 收藏」加入收藏；重复收藏给出提示。
- **取消收藏只能在「收藏」板块内**点「💔 取消收藏」——**必须先弹窗确认**才生效（题页不提供直接取消）。
- 顶部统计显示收藏数；**重置进度时收藏保留**（清空做题记录不删收藏）。

### 5.4 分区跳转（主观题桌面 + 手机，v1.2 新增）
- 顶栏「📂 分区」→ 按试卷/章节分组浏览（桌面：6 大区 46 分区；左侧分组树 + 右侧题目清单；手机：两级列表）。
- **点击题目前必须先弹窗确认**，确认后才跳转（自动切回顺序板块并定位该题）。

### 5.5 题号跳转修复（主观题，v1.2）
- 旧版只做题号精确匹配，而题库编号有 42 个空档 → 跳题误报“找不到”。现改为：题号精确匹配 → 位置兑底 → 仍不存在则给出提示（含最大题号 496）。

### 5.6 客观题桌面版考试导航顺序修复（v1.2）
- 题号导航颜色/成绩页“错题 · 第N题”序号原按**题库顺序**计算，与点击落地的**抽题顺序**不一致；现统一按抽题顺序（与导航完全对应）。

### 5.7 热点板块（主观题 + 大题，桌面 + 手机；v1.4 新增）
- 按全网高频（leetcode/dotcpp/嵌入式招聘要求）人工评分，取**出现率前 50% 的题数**标为热点：主观题 238/490、大题 83/170（含重复合并题加权与热门考点加权）
- 入口：顶栏「🔥 热点」板块（顺序练习旁）；名单在题库数据里（md `**热点：** 是` → JSON `hot: true`）
- 统计栏显示 🔥热点 N；热点板块内浏览/作答/看答案与顺序练习一致

### 5.8 分区窗口体验修复（主观 + 大题桌面，v1.4）

### 5.10 记忆模式（间隔重复 + 主动回忆）（主观题 / 大题，桌面 + 手机；v1.7 新增）
- **目标**：答题方式要能帮助记忆与理解，而不是「看一眼答案就过」。
- **主动回忆**：先点「💡 提示」，只显示 **题目解析** + **自评要点每行前 8 个字的线索**；想不起来再点「👀 查看参考答案」看完整答案。
- **自评三档**（看到完整答案后才出现）：😖 忘了 → 记忆盒回 0、遗忘次数 +1、明天再来；🤔 模糊 → 盒级退一级；😎 记住 → 盒级进一级。
- **间隔重复**：记忆盒 0~5 对应复习间隔 **1 / 1 / 3 / 7 / 15 / 30 天**；盒级 ≥4（≥15 天）记为「已掌握」。每题数据写在进度里新增的 `mem` 字段（`box` / `due` / `reps` / `lapses` / `last`，`due` 与 `last` 是日期序号整数）；旧进度没有 `mem` 时按「未开始」处理。
- **复习板块**：只放 **due ≤ 今天** 的题，按到期日、盒级升序；没有到期题但有记忆记录时，可提前复习最不熟的 10 道（没进记忆的优先，其次盒级低、遗忘次数多）；一条记忆都没有时提示先去顺序 / 热点板块自评。复习板块内点「忘了」会把本题排到本次队尾、稍后再来一遍。
- **状态显示**：桌面顶栏第二行 / 手机页面状态区显示 `记忆模式 · 待复习 N · 已掌握 N · 学习中 N · 今日自评 N`。
- **快捷键**（仅桌面）：`h` = 提示，`1` / `2` / `3` = 忘了 / 模糊 / 记住。
- **不动的部分**：考试板块逻辑不变；收藏、分区、热点、进度记忆保持原样。

### 5.11 答题区呈现（手机端：答案优先 + 代码块）（v1.8 新增）

- **顺序**：手机端查看答案时，先给 `✅ 标准答案`，再给 `📖 题目解析`，最后给 `📝 自评要点`；桌面端保持「解析 → 答案 → 自评要点」（先讲机理再给结论）。
- **卡片区分**：三块分别用绿色（答案）、蓝色（解析）、紫色（自评要点）卡片，标题行带 emoji。
- **代码块**：答案/解析里的代码自动渲染成深底等宽代码块；判定规则为「含 ASCII 结构字符（`#;{}()[]=&|<>`、`->`、`::`、`//`、`/*`）且中文不超过 6 字，或行首是预处理指令 / 缩进 ≥ 4 个空格」，纯中文讲解行按普通段落排版，不误判。
- **自评要点**：即「得分点」，必须是可逐条打分的评分要点（①…②…③…④加分：…），禁止写成「两种方法任一。」这类题面复读；入库前扫描得分点长度，不足 12 字的必须重写。
- **实现位置**：`面试题手机版-主观题\www\template.html` 与 `面试题手机版-大题\www\template.html` 的 `showAnsBox()`（桌面程序未改）。

## 七、已知约定与坑

1. **手机版 = 快照**：改题库必须重建网页和 APK（见"一"的注意）。
2. **解析器按行解析**：题块内出现行首 `#`、单独一行 `---` 会截断该题；代码里的 `#define` 等必须放进 ``` 代码块。
3. **不要重排已有编号**（会丢 `progress.json` 进度）。
4. 主观题/大题的 `**得分点：**` 之后的行会被当作得分点正文显示，合并说明写在末尾即可。
5. 测试脚本会临时改写 `题库.json` / `progress.json`：已用 `tests/progress_guard.py` 保护；`test_crash.py` 已加**题库快照**（`tests\题库.good.json`，启动校验+异常回滚）；若仍被强杀留下假题库 → 优先用快照回滚，否则 `core\build_bank.py` 重建。
6. Windows 终端里 PowerShell 写日志是 **UTF-16**，读日志要用 `encoding='utf-16'`；`python -c "…"` 里别写复杂中文/引号，改成脚本文件更稳。
7. GUI 测试在非前台会话里偶发不返回：一次只跑一个，输出重定向到文件后再读。
