# 要求文档 · 总说明

> 这里存放**每个项目的"要求 + 流程"文档**。规则很简单：

## 怎么用（很重要）

1. **我（AI）每次接到任务前，先读对应文档**，按里面的"标准流程"和"验收清单"执行；
2. **你可以随时直接修改这些文档**（增删判据、改流程、加规则）——我下次执行就按新版本走；
3. 做**新软件**时，第一步永远是先建一份同结构的文档（可直接复制本文档的模板），
   你确认/修改后我再动手写代码；
4. 文档里只写"**要求**（做成什么样）"和"**流程**（怎么一步步做）"，
   具体实现细节放在各项目自己的 README 里。

## 新项目模板（复制这段开始）

```markdown
# <项目名> · 要求与流程
> 版本 v1.0（YYYY-MM-DD）

## 一、目标与使用场景
## 二、功能要求（输入 / 输出 / 交互 / 边界）
## 三、数据与格式规范（文件、字段、命名、编号）
## 四、质量标准（正确性、可读性、容错）
## 五、标准流程（SOP：每次任务照做的步骤）
## 六、验收清单（Checklist）
## 七、已知约定与坑
## 八、变更记录
```
