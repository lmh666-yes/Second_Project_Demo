# Git 上传

把「一键上传到 GitHub」从 PowerShell 脚本升级为独立 Qt 桌面工具。

**这是一款独立程序，不属于「工具箱」。** 它自带 `src/`（Qt 源码 + Python 后端）与自己的配置，
放在 `本地工具/Git上传/`，与工具箱不共用源码、也不共用 `_toolbox.ini`。

## 打开方式

- 双击 `Git上传\运行.bat`

## 目录结构

```
Git上传\
├── GitUploader.pro
├── main.cpp
├── 运行.bat
├── 说明.md
├── src\                        ← Qt 源码 + Python 后端 git_backend.py
├── build\release\GitUploader.exe
└── _git_upload.ini             ← 本工具自己的配置（自动生成）
```

程序根由「从 exe 位置向上找含 `src/git_backend.py` 的那一层」确定，
所以整个 `Git上传/` 目录挪到哪一层都能跑。

## 五个页面

### ① 上传
- 选择项目文件夹（自动记住上次位置）
- 切换「账户配置档」（可存多套，一键切换）
- 输入提交说明（留空 = 自动用 `update 日期 时间`）
- 点「检查并上传」：自动执行 `add → commit → push`，带大文件保护（>100MB 拦住）；
  暂存默认排除 `build/`、`build_verify/`、`__pycache__/`、`tmp/`、`*.o`、`*.log` 等临时产物
- 点「预览变更」：先列出本次会提交哪些文件，确认后再传
- 点「拉取合并」：从远程同步到本地（遇到冲突会提示）

### ② 仓库状态
- 当前分支、远程地址、领先/落后远程几个提交
- 已暂存 / 已改动未暂存 / 未跟踪 文件数
- 最近 8 条提交记录
- 提交身份是否已配置
- 可直接「初始化仓库」或「绑定/修改远程地址」；绑定后会自动做一次连通性探测
  （`git ls-remote`），地址不合法会当场提示，探测不通只作提示不算失败

### ③ 账户设置
- 多配置档：每套 = 账户名 + 仓库地址 + 分支 + 提交身份（user.name / user.email）+ 默认文件夹 + 备注
- 新建 / 重命名（重名或原名不存在会拒绝）/ 删除 / 保存
- 提交身份可写「仓库作用域」（推荐）或「全局」
- 所有配置落地本目录下的 `_git_upload.ini`，拷走整个 `Git上传/` 目录连配置一起带走

### ④ .gitignore 助手
- 点「扫描」：自动识别目录里的编译产物（.o / .hex / Objects/ 等）
- 勾选要忽略的规则，一键写进 `.gitignore`
- 已有规则不会重复写入
- 右侧预览当前 `.gitignore` 内容

### ⑤ 运行日志
- 每次 git 操作的输出实时贴在这里
- 可「另存为…」或「清空」

## 命令行入口

```
Git上传\build\release\GitUploader.exe --selftest      # 自检
Git上传\build\release\GitUploader.exe --status D:\项目   # 打印仓库状态
Git上传\build\release\GitUploader.exe --where           # 查看后端/解释器位置
Git上传\build\release\GitUploader.exe --git-version     # git 版本
Git上传\build\release\GitUploader.exe --gui-smoke       # GUI 冒烟：开窗口点一遍安全按钮
```

## 与原脚本的关系

- 原 `本地工具/一键上传/push_to_github.ps1` 保留作为命令行后备
- 新工具功能更多：多账户配置、仓库状态总览、.gitignore 助手、大文件保护、失败原因自动解读

## 技术要点

- **Qt 界面 + Python 后端**：`src/git_backend.py` 执行全部 git 操作，Qt 只负责界面与调用
- **git 自动定位**：优先 PATH 里的 git，找不到再按常见安装位置找
- **防卡死**：HTTP 低限速 + 连接超时 + 凭据管理器不弹窗，避免地址打错时界面冻结
- **失败原因自动解读**：认证失败 / 非快进 / 仓库不存在 / 无提交 / 网络超时 等，都给中文提示
- **配置自持**：配置档落在本目录的 `_git_upload.ini`，不写工具箱的 `_toolbox.ini`

## 自检

```
Git上传\build\release\GitUploader.exe --selftest
```

或单独测后端：

```
python Git上传\src\git_backend.py gitver
```

`--selftest` 只跑纯逻辑，覆盖不到 GUI。窗口/样式/控件交互另用 GUI 冒烟出口：

```
Git上传\build\release\GitUploader.exe --gui-smoke            # 跑完打印 "GUI smoke 通过"
Git上传\build\release\GitUploader.exe --gui-smoke --shot d:\a.png
```

它会开窗口、遍历五个标签页、点一遍"不会弹对话框、不跑长任务"的按钮，并打印窗口实际尺寸与
最小尺寸。崩溃或卡死时进程不会正常收尾，**跑的时候建议外面套一个超时**。
（同一套出口在工具箱的程序里也有，见 `工具箱/说明.md`。）

## 重新编译

本工具与工具箱共用同一个构建脚本（它现在编两个 Qt 程序）：

```
python 本地工具\工具箱\构建.py            # 重编 Toolbox + GitUploader
python 本地工具\工具箱\构建.py --cleanonly # 只清中间产物（保留 exe 与 DLL）
```

> 工具链是**自动探测**的（`QTDIR` / `QT_ROOT` → 各盘 `\Qt` → PATH），
> 换电脑不用改脚本；找不到会给一条看得懂的报错。
> 手工 qmake 的老办法仍可用（`build\.qmake.stash` 里已存好编译器探测结果），
> 但新增头文件后必须重跑 qmake——交给构建脚本就不会忘。
