# 嵌入式工具箱（综合程序）

把工具箱内的各个工具合到一个 Qt 桌面程序里，一个窗口用全部功能。

- 两个 Qt 工具（项目起手助手、协议工作台）以页面的形式直接嵌进来，共用源码；
  2026-10 起它们**不再有独立入口**（外面的 exe 只是同一个程序的重复入口，已归档删除）。
- **单片机手册**（原 `本地工具\STM32速查\` 的独立桌面程序）也内置成页面，
  源码在 `shared\lookup\`，数据来自工具箱内的 `速查数据\data\dataset.json`。
- 八个命令行工具（进度扫描、引脚规划、RTOS 检查、编码守卫、链路仿真、LoRa 检查、协议校验、
  断网缓存）
  做成"运行器页"：在界面里填参数、点运行、看输出、一键打开报告，不必再逐个双击 bat。
- 另有 OTA 台架（包 `OTA\tools\ota_send.py` 的串口直连模式）与"全量检查"（依次跑完上面各检查）。

## 运行

双击工具箱根目录的 `打开工具箱.bat`（唯一入口），或直接双击
`程序\嵌入式工具箱\build\release\Toolbox.exe`。运行库已随 exe 打包。

命令行自检（不开界面，验证内嵌工具的逻辑；`--selftest` 里也会跑速查的
数据装载、条目计数与 28 例搜索基线）：

```
build\release\Toolbox.exe --selftest
```

速查页保留原独立程序的命令行出口（数据定位、搜索回归、打分明细）：

```
build\release\Toolbox.exe --where
build\release\Toolbox.exe --search [--sec ref|guide|build] [词...]
build\release\Toolbox.exe --explain [--sec ...] 词
build\release\Toolbox.exe --topics
```

**Ctrl+K 全局搜索**：一个框同时搜「页面名 / 检查项（各报告的命中项小节）/ 手册条目」，回车直达。

## RTOS 骨架生成

读移植好的工程里的 `FreeRTOSConfig.h`（可点「用板1配置 / 用板2配置」直接取本仓库的），
按「任务清单」与「资源清单」生成 `main.c` 骨架：任务参数宏、资源句柄、任务函数桩
（函数体是 TODO，带职责注释）、句柄创建与 `xTaskCreate`、`vTaskStartScheduler`。
生成前按配置校验：优先级是否越界、栈是否小于 `configMINIMAL_STACK_SIZE`、
任务栈合计是否超 `configTOTAL_HEAP_SIZE`、用了互斥量/计数信号量/软定时器但对应
`configUSE_*` 未开、是否缺 `configASSERT`。输出可选 GBK（对齐 `main.c` 口径）或 UTF-8。

任务表有「关联资源」列：填资源变量名（可多个，逗号分隔），生成的代码里该任务的函数桩
会直接引用这些名字。点「按任务串联资源」可按任务顺序给相邻任务之间自动建队列
（`s_q_<上游>_to_<下游>`），并双向写进两个任务的关联资源、补进资源表；若关联了未声明的资源，
校验会提示「关联」类告警。

### 从「单片机手册」取补全素材（两级）

生成器直接读 `工具箱\速查数据\data\dataset.json`（与速查页同一份数据，只读不改），
把"手册"变成"生成时的素材"：

- **符号级**：任务表的「补全提示词」列填函数前缀 / 关键词（如 `xQueueCreate`、`SHT30`），
  生成时把速查里查到的**原型 + 用途**做成一撮注释贴在任务桩里，省得来回切页面抄。
  查不到会明说"没查到"，不会静默留白。
- **代码段级**：下方「参考代码段」区列出全部流程卡（39 张，如「① 串口 USART + DMA + 空闲中断接收」），
  勾选后把该卡的**整段代码**拼进生成物的参考区，按卡号排序（数据作者已按 时钟→引脚→外设→NVIC 排好）。
  卡里的 `#include` 与 `main()` 会被去掉（39 张里有 16 张含 `main()`，直接拼会出现第二个 main），
  其中的 `*_Init` 函数名会写进 `main()` 的调用提示。

> 该数据 4MB：清单在本页**首次显示时**才载入，不会拖慢工具箱启动。
> 这两条都有自检守着（"数据找得到" + "生成物真的含预期片段"），数据挪窝了会直接 FAIL。

## 运行器页的操作

- 统一提供：运行 / 停止 / 清空输出 / 复制全部 / 另存为… / 打开报告，快捷键 Ctrl+R 运行、Ctrl+O 打开报告。
- 输出区带**查找框**（回车跳到下一处）与**自动滚动到底**开关，长输出不会错过结尾。
- 「打开报告」在每次运行结束后自动刷新可用性——第一次运行完即可点击，不需要重启程序。
- Python 解释器在运行时自动探测（依次尝试 `python`、`py -3`、`python3`），无需手工配置。
- 进程输出按 UTF-8 解码，中文不会乱码。
- 若工具箱目录解析失败，页面顶部会显示红色告警，而不是等到点运行才报错。
- **多步检查**（如"全量检查"）跑完后，末尾会打印一张逐项汇总表，一眼看出哪项没过。

## 工程体检总览（可视化）

「汇总」组的工程体检总览页把各检查结果画成图，一屏看清项目健康度：

- **健康度卡片**：七个检查器各一张，状态点（绿 / 黄 / 红）+ 关键数字（冲突数、严重数、违规数…）；
  数量类指标 **1~4 处黄 / ≥5 处红**，断网缓存再按"可扛时长 <10 分钟红 / <30 分钟黄"分级，红黄线写进悬停提示
- **引脚占用热力图**：每块板一张 A~G × 0~F 网格，空闲 / 占用 / **真冲突** / 声明未用·重叠 四态；
  板表里有几块就画几块（含 OTA 工程），一行放不下自动换行。
  「真冲突」= 同一脚被 ≥2 个**工程里真启用**的模块声明；库里成对声明、工程还没启用的
  只算「声明重叠」（同紫色，悬停提示会说明），不会染红 —— 免得满屏红字却不知道先改哪个
- **Flash / RAM 占用条**：读 Keil 复编日志的内存快照，对照芯片上限（F407ZE 512KB Flash、F407ZG 1MB Flash；两者 RAM 均 192KB）
- **RTOS 任务**：任务名 / 优先级 / 栈（有任务时才画）
- **进度趋势**：待办与桩的历史折线，**悬停某个点看那一轮的日期与两个读数**

数据来源是各检查器新加的 `--json`（结构化输出），不是解析 md 报告 —— 面板只认结构化数据，免得文本格式一改就崩。
首次切到本页会自动取数一次，也可点「刷新」；取数要跑七个 Python，所以构造时不取数，以免拖慢工具箱启动。
每轮取数会归档一份快照到 `_体检历史/`（只留最近 20 份），「历史回看」页签据此重渲染任意一轮，
并可**任选对比基准**（默认跟上一轮比）。

**交互**：

- 鼠标悬停引脚格子 → 提示该脚被谁占用（空闲则显示"空闲"；声明未用的标紫并说明"库内声明了但没人引"）
- 鼠标悬停趋势折线的点 → 显示那一轮的日期与待办/桩读数
- 点健康度卡片 → 跳到对应的工具页（点「引脚规划」卡就进引脚规划页）
- 状态栏显示取数时刻（`已取数 7 / 7 · 20:57:16`），一眼知道数据新不新
- 趋势图 Y 轴自适应（从最小值下方到最大值上方），左侧标出上下界 —— 免得曲线被压成一条平线
- 「报告原文」页签可开「**只看命中项**」：只留各报告的发现/冲突/违规等小节，长报告不用一路滚
  （Ctrl+K 里点「检查项」就是跳到这里并定位）

各检查器都支持 `--json`（只输出 JSON、**不写 md 报告**，便于脚本与面板调用）：

```
python 检查\引脚规划\pin_planner.py --json
python 检查\RTOS检查\rtos_check.py --json
python 检查\编码守卫\encoding_guard.py --json
python 检查\进度跟踪\progress_scan.py --json
python 检查\LoRa检查\lora_check.py --json
python 检查\协议校验\protocol_check.py --json
python 检查\断网缓存\cache_check.py --json
```

另有截图出口，用来验证面板真的画出了东西（`--gui-smoke` 只证明不崩，看不到画没画）：

```
build\release\Toolbox.exe --shot-overview out.png
```

还有两个**量测出口** —— 把界面规范与启动/切页耗时用数字卡住，而不是靠感觉（F1 / F2）：

```
build\release\Toolbox.exe --ui-audit      # 界面规范检查：按钮高度/字号、标签栏、滚动条、页左外边距
                                          # 各只许一种；按钮文字不许被裁；页最小尺寸不超 740×654
                                          # （再大主窗口在 1024×768 屏上就放不下）。打印实测分布 +
                                          # 「UI 规范 → 通过/不达标」，不达标退出码 2。
build\release\Toolbox.exe --perf-probe    # 性能量测：解释器探测首次/再次、冷启动（构造全部页面）、
                                          # 显示+首帧、逐页首访。判定线：冷启动 ≤1500ms、
                                          # 单页首访 ≤800ms，超了退出码 2。
build\release\Toolbox.exe --mutation-selftest
                                          # 变异自测（H7）：把每个检查器**故意改坏一处判定**（在各
                                          # 脚本同目录造临时副本、跑完即删），断言它自己的 --selftest
                                          # **必须变红** —— 守住"自检真的在测那一条"，而不是"永远全绿"。
                                          # 每处先跑一遍没改坏的原脚本作对照。全部能变红 → 退出码 0。
```

> 三个出口都只是**量测 / 自测**，不参与构建；`--ui-audit` 会切遍侧栏全部页（含首访取数），跑完自行退出。
>
> **带参数运行（上面这些测试 / 量测出口）不会动你的本机设置、也不会动你的体检历史**：
> 它们会把 `_toolbox.ini` 与 `速查数据\_stm32lookup.ini` 各拷一份到 `%TEMP%\toolbox_probe_ini\`，
> 之后读写都落在副本上 —— 主题、行尾检查开关、"最近浏览"这些不会被测试改掉。
> 同时还会把两份**历史**也拷进沙箱（`_体检历史\*.json` 与
> `检查\进度跟踪\_progress_history.json`）—— 否则每跑一轮截图/冒烟/量测，就往
> 「历史回看」和"待办 / 桩"趋势里塞一轮测试数据，把你自己的真跑稀释掉。
> 不带参数正常启动不走这条路，设置与历史照常记在你自己的文件里。

## 跨工具联动

- **链路仿真 → 协议工作台**：跑完仿真后点「发送到协议工作台」，自动把
  `检查\链路仿真\产物\link_<场景>.hex` 填进解帧页并切过去，省去手工复制。
- **链路仿真 → 协议校验（两板端到端回放）**：仿真产物是"板1 组帧"的字节流，可直接喂给
  协议校验的拆包器（按板2 的常量拆帧并解出物理量）：
  `python 检查\协议校验\protocol_check.py --replay 检查\链路仿真\产物\link_normal.hex`
  —— 这就是"板1 组帧 → 板2 解帧"的闭环验证，比只比字节流更接近联调现场。
- **配置记忆**：窗口大小与位置、所在页、引脚板选与模块、链路场景与帧数、
  编码换行选项、OTA 模式与端口、起手助手的导出目录、**首次运行向导是否已弹**，都会记住，下次打开保持原样。
  状态存在 `工具箱\_toolbox.ini`，换机器拷走整个 `工具箱\` 连状态一起带走。
  速查页的收藏 / 最近 / 向导进度勾选与上次板块另存一份，记在
  `速查数据\_stm32lookup.ini`（与并入前一致，收藏不会丢）。
  两处的「主题」按钮切的是同一套全局主题（`_toolbox.ini`）。
- **设置页的「清理」组**：可手动删过期体检快照（保留最近 20 份，与刷新时自动滚动的口径一致）
  与检查产物（各检查器 `*报告.md`，跑一次检查即重新生成）。


## 与「仓库巡检」的分工

两处都叫"检查"，管的事不一样、不重叠：

- **本工具箱（`检查\` 各运行器 + 全量检查）**：只读源码 / 产物，做**本地静态检查**——
  编码与 BOM、中断与优先级、引脚占用、LoRa 配置一致性、协议常量与命令字、断网缓存容量、
  待办与桩函数统计。几秒到几十秒跑完，改代码时随手就点。
- **`本地工具\仓库巡检\最终验证.ps1`**：跨端**复编验证**——qmake + mingw32-make 复编 Qt 上位机、
  用 Keil 全量复编板1 / 板2 两个工程（统计 Error / Warning）、再跑文风检查；是"出包前"那一道。

交叉点只有一个：巡检脚本里 SerialMonitor 的 `--selftest`（既有 1/18 个失败项）与
`--cmdselftest`（既有崩溃）是那个 Qt 上位机自己的历史问题，与本工具集无关，
在结论表里标成「已知」、不计入 FAIL；加 `-SkipSerialMonitor` 可跳过这两项。
**根因（2026-10-17 查清）**：它的 `frameparser.cpp` 里 `FrameProto::buildEnv` /
`FrameParser::feed` / `takeFrame` / CRC / unpack 全是 `TODO(阶段2)` 骨架（函数体直接返回空），
所以自检 17/18 必然落空、`--cmdselftest` 随之崩 —— 那是它**未实现的阶段2**，
不是本工具箱的回归，**不在本工具箱的维护范围**（要修等于替它重写整个协议层）；

## 关于 shared\ 为什么是英文名

qmake 读不了 `.pro` 里的中文路径（会按系统码页解析导致找不到文件，且不接受 UTF-8 BOM）。
因此本程序与其内嵌页面共用的源码放在 ASCII 名的 `shared\` 下，`.pro` 用相对路径
`../../shared/...` 引用，避免复制代码、保持单一源。

## 运行器页需要 python

运行器页用 `QProcess` 调用 `python <脚本>`。程序会在启动时从自身位置向上查找工具箱根目录
（含 `程序`、`检查`、`shared` 三个目录的那一层），因此 exe 要留在 `工具箱\` 内。
若命令行执行不了 `python`，运行器页会给出提示——装一个 Python 并勾选 Add to PATH 即可
（不再提供各工具自己的 `.bat` 入口，那些入口已随去子程序一并删除）。

## 重新构建

改 `shared\` 或本目录里的源码后，用工具箱根目录的构建脚本重编：

```
python 构建.py            # 重编两个 Qt 程序：本程序 + 同级的 Git上传
python 构建.py --cleanonly  # 只清中间产物（保留 exe 与 DLL）
```

> 为什么不是直接 `qmake`：qmake 生成 Makefile 时要探测编译器的默认 include / lib 路径，
> 本机环境下这一步会失败（报 `failed to parse default include paths from compiler output`）。
> `构建.py` 会先把探测结果写进各 `build\.qmake.stash`，qmake 读缓存就跳过探测。
>
> 工具链不写死：按 `QTDIR` / `QT_ROOT` 环境变量 → 各盘 `\Qt` / `\Qt6` → PATH 的顺序找
> Qt 的 mingw kit 与配套 MinGW；找不到会给一条看得懂的报错（提示装什么、或设哪个变量）。

## 本轮升级要点（2026-10-14）

- **主题**：`shared/common/theme.*` 提供深色 / 浅色两套科技简约风 QSS，侧栏一键切换，
  选择记在 `_toolbox.ini`；整个程序统一应用（现在只有这一个程序）。
- **帮助面板**：侧栏「帮助 / 快捷键」，含建议顺序、快捷键、主题与联动说明。
- **RTOS 骨架生成增强**：
  - 生成 **`.h` + `.c` 两件套**（句柄 extern、任务原型）；
  - **`/* USER CODE BEGIN */` 保护区**，重新生成不覆盖你写的代码；
  - 资源/任务创建点**返回值判空**；
  - 输出 **`FreeRTOSConfig.h` 建议片段**（优先级、栈、堆、功能开关、`configASSERT`）；
  - **场景模板**（采集端 / 网关端 / 最小入门）一键套用；
  - **从起手助手导入**任务表（约定：任务名 / 周期ms（事件填 0） / 优先级 / 栈(字) / 职责）；
  - 输出可选 **GBK / UTF-8** 与 **LF / CRLF**。
- **即时校验**：任务表与资源表任一改动即自动重算校验结果。
- **工程体检总览页**：把进度 / 引脚 / RTOS / 编码 / LoRa / 协议校验 / 断网缓存 七份报告的关键结论聚到一屏。
- **稳定性**：运行器页加单步超时看门狗（默认 120 s 自动终止）。
