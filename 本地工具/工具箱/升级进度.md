### 2026-10-17 · 移植性修复（换台电脑能不能跑）

你问"移植性能不能在不同电脑上跑"，实测 + 修掉一个**阻断级**问题：

- **发现**：`Toolbox.exe` 的 `build\release` 里只有 Qt6 DLL 与插件，**缺 3 个 MinGW 运行库**
  （`libgcc_s_seh-1` / `libstdc++-6` / `libwinpthread-1`；同级 `Git上传` 有、工具箱没有）——
  于是在"PATH 里没有 Qt"的机器上以 `0xC0000135` 连窗口都起不来（本机因为在 PATH 里有 Qt 才没暴露）。
- **修**：① 三个运行库补进 `build\release`；② `构建.py` 每次编译成功后自检 `release\` 的运行库
  与插件目录、缺的自动从工具链补齐、补不到就大声报（不让"能编过"骗成"能跑"）；
  ③ 顺带补 `sys.stdout` UTF-8（英文 Windows 上中文提示不乱码）。
- **实测结论**：clone 整仓到任意路径/盘符可用（包含带空格+中文的路径，PATH 抹掉 Qt/MinGW 后
  三个探针仍全过）；只把 `工具箱\` 单目录拷出去时，GUI/手册/工程模板可用，但检查类功能失效
  （要读工程源码）、OTA 脚本定位失败（在仓库根 `OTA\tools\` 下）——已写进 `说明.md`「跨机运行」一节。
- 验证：`--selftest` 失败项 0 · `--gui-smoke` 通过 · `--shot-overview` 命中区 261 / 趋势点 30，
  退出码 0 · **错例**：临时挪走 `libwinpthread-1.dll` 后重编，构建脚本报"补运行库"并把文件补回。
