# 断网缓存核算

回答两个问题：

1. 板2 的 W25QXX 滚动日志（`w25qxx_log.h` 划出来的环形区）断网时**能扛多久**？
2. **补传会不会比写入慢** —— 那样缓存会被"边补边覆盖"，还没补上的数据直接丢
   （`w25qxx_log.h` 里 `W25QXX_LogLost` 非 0 就是这种现象）。

## 用法

在工具箱窗口「检查 → 断网缓存」页点「运行」，或命令行：

```
python 本地工具\工具箱\检查\断网缓存\cache_check.py
python 本地工具\工具箱\检查\断网缓存\cache_check.py --period-ms 1000 --replay-ms 50
python 本地工具\工具箱\检查\断网缓存\cache_check.py --record-bytes 24
python 本地工具\工具箱\检查\断网缓存\cache_check.py --json
python 本地工具\工具箱\检查\断网缓存\cache_check.py --selftest
```

报告生成在本文件夹：`断网缓存报告.md`（每次覆盖）。只读脚本，不改任何源码。

## 事实来源

| 数据 | 来源 |
|---|---|
| 缓存几何（槽位大小 / 头部长度 / 扇区数 / 基址） | 板2 `FWLIB\inc\w25qxx_log.h` |
| 分区上界与扇区大小 | 板2 `FWLIB\inc\w25qxx.h` |
| 上传周期、补传每条耗时、线上记录字节数 | 命令行参数（默认 1000ms / 50ms / 20B，**只是示例**） |

## 检查项

| 项 | 内容 | 等级 |
|---|---|---|
| 记录不跨扇区 | `SLOT_SIZE` 须为 4 的倍数且能整除扇区大小 | 严重 |
| 头部小于槽位 | `HDR_SIZE < SLOT_SIZE`，数据段 = 槽位 − 头部 | 严重 |
| 记录装得下 | 线上记录字节数 ≤ 单条载荷；正好相等时提示"没有余量" | 严重 / 注意 |
| 分区边界 | 日志区 `BASE + SECTORS × 扇区` 不得越过下一个分区上界 | 严重 |
| 补传 vs 写入 | 补传每条耗时 > 上传周期 → 补不完、边补边覆盖；否则给出追平时间 | 严重 / 注意 |
| 扇区粒度丢失 | 整扇擦除会连带丢掉同扇区未读记录（`W25QXX_LogLost` 的来源） | 注意（提示） |

> B2：报告「发现」一节里，**"没有余量 / 补传余量小 / 扇区连带丢失"这三条「注意」各自紧跟
> 一条「改法 + 验收」** —— 改哪几个宏、改完怎么验（重跑本工具看哪个数、或做什么实测看
> 哪个计数器），不用再自己琢磨。

## 参数

| 参数 | 作用 |
|---|---|
| `--period-ms <毫秒>` | 上传周期（默认 1000）；一次上报写多条时按等效周期填 |
| `--replay-ms <毫秒>` | 补传一条的耗时（默认 50） |
| `--record-bytes <字节>` | 线上一条记录的数据字节数（默认 20 = 原始环境帧） |
| `--quiet` / `--json` | 只打印摘要 / 结构化输出 |
| `--selftest` | 内存里造宏文本核对 31 项判定（错例必命中、反例不误报，含三条"注意"的改法/验收） |

未知参数会报错并列出可用参数。

## 说明

- 缓存几何**全部读自工程真值**，不内置任何印象数据；宏名或取值改了会自动跟上。
- 宏算不出来（缺失 / 写成类型或函数调用）时**报严重而不是静默通过** ——
  静默通过等于给一个没核算过的缓存盖章。
- "断网可扛"按"每个上传周期写 1 条"估算；结论依赖你填的周期，填错就白算。
