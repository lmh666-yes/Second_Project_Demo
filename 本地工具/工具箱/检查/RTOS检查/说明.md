# FreeRTOS 安全检查器

静态检查两块固件里的 FreeRTOS 硬约束，命中项逐条附原理。用于"边写边学"阶段，
把优先级、栈、ISR 误用这几类坑在编译前挡住。

## 用法

在工具箱窗口「检查 → RTOS 检查」页点「运行」，或命令行：

```
python 本地工具\工具箱\检查\RTOS检查\rtos_check.py
python 本地工具\工具箱\检查\RTOS检查\rtos_check.py --selftest
```

- 报告生成在本文件夹：`RTOS检查报告.md`（每次运行覆盖）。
- `--selftest` 用一组故意写错的合成工程验证检查确实命中，不写报告。

## 检查项

| 项 | 内容 | 等级 |
|---|---|---|
| 中断优先级（按实际调用判定） | 调了 `xxxFromISR` 的 ISR，其抢占值是否 >= `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY`；值取 `FWLIB\src` 里实际配下去的，不看宏声明 | 严重 |
| 优先级宏提示 | `FWLIB\inc` 里 `SYS_*_IRQ_PRE_PRIO` 低于内核上限（该中断一旦用 FromISR 就越界） | 注意 |
| NVIC 分组 | 是否为 `NVIC_PriorityGroup_4`（4 位抢占） | 严重 |
| ISR 误用 | 从 `*_IRQHandler` / `*_isr` / `*_irq` / `*_dispatch` 起按调用关系往下追（宏展开一层、函数最多三层）后调任务态接口；含 ISR 里进内核临界区 | 严重 / 注意 |
| 共享变量缺 volatile | 被 ISR 写入、任务态代码里也读写的文件作用域变量，声明里没有 `volatile` | 注意 |
| 任务栈 | `xTaskCreate` 栈深度（单位：字）是否过小 | 注意 |
| 堆预算 | 任务栈合计是否接近 `configTOTAL_HEAP_SIZE` | 注意 |
| configASSERT | 是否定义（未定义则优先级违规不会被当场发现） | 注意 |

## 说明

- 中断优先级上限默认取 `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY`；
  该值来自 `FreeRTOSConfig.h`。
- 静态检查只覆盖能判定的部分，命中项需人工确认上下文。
- 只读脚本，不改任何源码。

## 规则表（数据模型，外置）

"哪些接口不适合在中断里调"不写死在脚本里，而是放在
`工具箱\速查数据\rules\freertos_isr_rules.json`：

- 三张表：`blocking_api`（任务态接口，ISR 里调判严重）、`isr_unsafe_critical`
  （内核临界区，ISR 里要改用 `*_FROM_ISR`）、`rtos_prefix`（其余 RTOS 接口判注意）。
- 同一个文件也被 RTOS 骨架生成器读（拦"勾选的参考卡里 ISR 调了任务态接口"）——
  **一份数据两处用**，加接口只改表，不用动脚本、不用重编。
- 表缺失/损坏时本脚本回退到内置同名表（行为与老版本一致），自检会 FAIL 提示表没装到。
- 表里只放 FreeRTOS 自身的 API 规则，**不含芯片手册数据**：外设/引脚/中断实际优先级
  一律从工程真值里扫出来，不内置凭印象写的对照表。

## 命令行参数

| 参数 | 作用 |
|---|---|
| `--out <文件>` | 指定报告输出路径，默认 `RTOS检查报告.md` |
| `--quiet` | 只在控制台打印摘要，不打印按板卡清单 |
| `--selftest` | 跑内置自检（故意造错例，抓不到即 FAIL） |

未知参数会报错退出并列出可用参数（退出码 2），不会静默忽略——
否则拼错一个开关会跑成一次全量真实扫描并覆盖报告。

> 本目录随仓库入库（`本地工具/` 已纳入版本管理）；中间产物与本机状态 `_*.ini` 不入库。
