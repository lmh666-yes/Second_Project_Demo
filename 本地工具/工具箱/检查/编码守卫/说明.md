# 编码与仓库守卫

守住工程的两条编码口径，防止中文注释被编辑器改坏；并顺带给出内存占用快照。

## 口径

- 两份 `main.c` 为 GBK(936) 编码；
- 其余源码与文档为 UTF-8 无 BOM；
- 仓库索引中的换行为 LF。

## 用法

在工具箱窗口「检查 → 编码守卫」页点「运行」，或命令行：

```
python 本地工具\工具箱\检查\编码守卫\encoding_guard.py
python 本地工具\工具箱\检查\编码守卫\encoding_guard.py --eol
python 本地工具\工具箱\检查\编码守卫\encoding_guard.py --selftest
```

报告生成在本文件夹：`编码守卫报告.md`（每次运行覆盖）。只读脚本，不改任何源码。

## 检查项

| 项 | 内容 | 何时查 |
|---|---|---|
| BOM | UTF-8 / UTF-16 BOM 一律报 | 默认 |
| 编码 | main.c 须能按 GBK 解码；其余须能按 UTF-8 解码 | 默认 |
| 编码（启发式） | 能按 GBK 解码、但内容更像 UTF-8（含中文）也报 | 默认 |
| 乱码 | 解码后含替换字符 U+FFFD | 默认 |
| 换行 | git 索引里的换行须为 LF | 加 `--eol` |
| 内存快照 | 读 Keil 日志的 Program Size（Code/RO/RW/ZI） | 默认 |

## 关于换行为什么默认不查

本机 git 若设了 `core.autocrlf=true`，签出到工作区的 UTF-8 文本会被自动转成 CRLF，
直接看工作区字节会把整库都误报成 CRLF。所以换行检查只对 git 索引做，且需 `--eol`
显式启用。可用 `git config --get core.autocrlf` 查看本机设置。

## 说明

- 只扫口径覆盖的源码与文档（.c/.h/.cpp/.hpp/.md/.txt/.pro/.json/.ui），跳过第三方、
  构建产物与参考素材（FreeRTOS / ETH / RTE / qcustomplot / build / 双版资源）。
- 有违规时进程退出码非 0，便于接进自动化。

> 本目录随仓库入库（`本地工具/` 已纳入版本管理）；中间产物与本机状态 `_*.ini` 不入库。
