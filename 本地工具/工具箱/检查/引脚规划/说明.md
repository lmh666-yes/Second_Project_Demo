# 引脚与资源规划器

按模块看引脚与中断资源，并在选定一组模块后报出它们之间的冲突。
与 `仓库巡检/pin_audit.py` 的分工：pin_audit 只做全板体检，本工具用于"开工前选脚"。

## 用法

在工具箱窗口「检查 → 引脚规划」页点「运行」，或命令行：

```
python 本地工具\工具箱\检查\引脚规划\pin_planner.py
python 本地工具\工具箱\检查\引脚规划\pin_planner.py --use "LORA_E22,W25QXX,RS485"
python 本地工具\工具箱\检查\引脚规划\pin_planner.py --board 2 --quiet
python 本地工具\工具箱\检查\引脚规划\pin_planner.py --selftest
```

报告生成在本文件夹：`引脚规划报告.md`（每次运行覆盖）。只读脚本，不改任何源码。

## 报告内容

| 节 | 内容 |
|---|---|
| 总览 | 每板的头文件数、占用脚、**真会撞**数、仅声明重叠数、空闲数 |
| 方案检查 | 给出 `--use` 时，选中模块之间的冲突与引脚清单 |
| 模块与引脚 | 每个宏基名占用的引脚（基名、归并后的模块名、引脚、出处） |
| 冲突引脚（真会撞） | 同一脚被 ≥2 个**工程里真启用**的模块声明 → 后 init 的会覆盖前一个，要动手改 |
| 仅是声明重叠 | 同一脚被多个宏声明，但工程里只启用了其中一个（其余是还没启用的模块）→ 潜在，不染红 |
| 调试口被占用（严重） | SWD/JTAG 的脚（PA13/PA14/PA15/PB3/PB4）被**工程里真启用**的业务宏占用 → 自断下载与在线调试通道 |
| 调试口仅被声明占（潜在） | 占调试口的宏工程里还没启用 → 等你启用那个模块时再处理 |
| 无人认领引脚 | 库里没有任何模块声明的脚（选空闲脚先看这里） |
| 声明了但没人用（僵尸宏） | 头文件里声明了 `_PORT`/`_PIN`，但**连库里都没人引**；回收代价最低（比"工程没启用"更严） |
| 中断资源 | 可静态解析的 IRQn 与抢占/子优先级；抢占低于内核上限会标出 |
| DMA 资源 | 工程里真实写下来的数据流/通道占用；同一条流被多个模块用会单独列出 |

## 参数

| 参数 | 作用 |
|---|---|
| `--use <前缀,...>` | 指定一组模块基名前缀，只对它们做冲突预检 |
| `--board 1\|2` | 只处理某一块板 |
| `--out <文件>` | 指定报告输出路径 |
| `--quiet` | 只打印摘要 |
| `--selftest` | 在临时目录造合成板核对 47 项判定（含两级冲突、两级调试口、两种 NVIC 写法、僵尸宏错例与启用反例），不写报告 |

未知参数会报错并列出可用参数（以前是静默跳过）。

## 说明

- 引脚来自 `FWLIB\inc\*.h` 里成对的 `*_PORT` / `*_PIN` 宏，与 pin_audit.py 同口径。
- IRQn 由函数形参传入的写法（如按序号配置的 USART/TIM）无法静态解析，不列出。
- "无人认领"不等于硬件上一定空着，是"库里没有模块声明"。
- "声明了但没人用"的判据很硬：基名除了自己的声明头之外，工程里任何 `.c`/`.h` 都找不到第二次出现
  （注释与字符串先掩掉，免得"注释里提了一句"就算用了）。命中的脚也**不等于**硬件空着，
  可能要对照原理图确认，并确认不是"别的宏绕开了它"。
- DMA 一节只统计工程**自己写下来**的占用：`FWLIB\inc` 里的 `*_DMA_STREAM` / `*_DMA_CHANNEL`
  宏，以及 `.c` 里把 `DMAx_Streamn` 字面量传进 DMA 接口、赋给字段或被 `return` 出去的写法。
  驱动内部的枚举表（`dma_irqn()` 数组、X-Macro 清单、指针范围比较）与注释不算占用。
  流由形参/字段传进去的调用（`p->tx_stream`、`stream`）静态判不出，单列成"无法静态解析"。
  **不内置芯片手册的"外设-通道"对照表**：那张表得对着数据手册核，凭印象写出来是害人。

> 本目录随仓库入库（`本地工具/` 已纳入版本管理）；中间产物与本机状态 `_*.ini` 不入库。
