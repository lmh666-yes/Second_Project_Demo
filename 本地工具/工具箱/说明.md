# 嵌入式工具箱

一套面向本工作区的自建工具，覆盖起手设计、进度、协议、引脚、RTOS、编码与无硬件联调。
工具来源与排期见同目录的 `工具规划.md`。

## 打开方式

**双击本目录下的 `打开工具箱.bat`**（唯一入口）——一个窗口里就包含全部工具。

2026-10 起，工具箱里不再有独立子程序：
「项目起手助手」「协议工作台」本来就是这一个程序里的页面，它们各自的 exe / `.pro`
只是重复入口，已连源码一起归档到
`本地工具\归档\20261015_工具箱去子程序_入口与源码.zip`（删掉可回退）。
**STM32 速查**（原独立桌面程序）也一并并入，源码在 `shared\lookup\`，
数据管线（`dataset.json` / 基线 / 导出脚本 / 重建链）**搬进了 `速查数据\`**，
原来那个同级的 `STM32速查\` 目录已删除；它的独立 exe / `.pro` / `main.cpp` 归档到
`本地工具\归档\20261015_STM32速查桌面版并入工具箱.zip`。
五个检查工具的命令行 `.bat` 入口也一并收掉了——程序内部直接调 Python 脚本，
不需要再开黑窗口，也就不会再出现"到底该双击哪个"的困惑。

## 目录结构

按用途分组，源码与产物分开：

```
工具箱\
├── 检查\                     ← 五个命令行检查工具（由程序内部调用，无独立入口）
│   ├── 进度跟踪\              扫描 TODO 与桩函数
│   ├── 引脚规划\              引脚占用、冲突、中断资源、DMA 数据流占用
│   ├── RTOS检查\              优先级、NVIC、ISR、栈与堆
│   ├── 编码守卫\              编码 / BOM / 换行 / 内存快照
│   └── 链路仿真\              无硬件时生成字节流（产物在 产物\ 子目录）
├── 程序\                     ← 唯一的程序：嵌入式工具箱（一个窗口集成全部）
│   └── 嵌入式工具箱\
├── shared\                   ← 该程序用的共享源码（common / kickstart / protocol / lookup）
├── 速查数据\                 ← 速查页的数据管线（不是工具，是数据）
│   ├── data\                  dataset.json（1004 条，约 4MB）+ search_baseline.txt（28 例）
│   └── tools\                 export_json.js（导出）+ rebuild.bat（一键重建整条链）
├── 打开工具箱.bat            双击即开（推荐入口）
├── 构建.py                   重新构建程序（或 --cleanonly 清中间产物）
├── 说明.md                   本文件
├── 工具规划.md               工具来源、取舍与排期
└── _toolbox.ini              界面状态记忆（窗口几何、选项等），自动生成
```

- 程序把「项目起手助手」「协议工作台」以页面形式内嵌，五个命令行工具做成"运行器页"，
  另有"全量检查"页依次跑完五个命令行检查。**STM32 速查**也是内嵌页（源码 `shared\lookup\`），
  数据在 `速查数据\data\dataset.json`，4MB 只在**首次切到该页时**才装载。
  详见 `程序\嵌入式工具箱\说明.md`。
- 改了 `shared\` 下的源码后跑 `python 构建.py` 重编。
  这个脚本现在编**两个** Qt 程序：工具箱内的 Toolbox + 同级的 `Git上传`（它是独立程序，
  只是共用这一个构建脚本）。工具链自动探测（`QTDIR`/`QT_ROOT` → 各盘 `\Qt` → PATH），
  换电脑不用改脚本；找不到会给一条看得懂的报错。
- 数据更新与整条重建链（含手机版 / APK）见 `速查数据\说明.md`。
- 每个命令行工具目录里只放脚本、说明与其报告；链路仿真的字节流产物另放 `产物\`。

## 与 `本地工具/` 下其他目录的关系

- 工具箱内是本次新建的工具。
- `本地工具/` 下的其他目录（一键上传、仓库巡检、标准库速查、标准库速查手机版、面试刷题）
  为原有工具，保持原位，不在本工具箱内。
- **STM32 速查**的桌面端已并入本工具箱（页面「STM32 速查」，源码 `shared\lookup\`）；
  数据管线也一起搬了进来（`速查数据\`），原来同级的 `本地工具\STM32速查\` 已删除。
  网页版（`标准库速查\`）与手机版（`标准库速查手机版\`）仍保持原位，是数据的源头与另一条线。
- **Git 上传**同样是一款独立程序，不属于工具箱，放在 `本地工具/Git上传/`：
  自带 `src/`（含 Python 后端 `git_backend.py`）与自己的配置 `_git_upload.ini`，
  不与工具箱共用源码、也不共用 `_toolbox.ini`。
- `本地工具/` 整体不入库（`.gitignore` 已忽略）。

> 已知依赖：编码守卫的"内存占用快照"取自 Keil 复编日志，查找位置为工具箱目录及其各上级目录下的
> `仓库巡检/验证日志/`。当前日志在 `本地工具/仓库巡检/验证日志/`，可正常取到；若日志缺失，
> 报告会显式列出缺项，不再静默留空。

## 命令行自检

每个工具都带自检，且自检会故意构造错例验证"确实能抓到问题"：

```
python 检查\编码守卫\encoding_guard.py --selftest
python 检查\RTOS检查\rtos_check.py --selftest
python 检查\链路仿真\link_sim.py --selftest
python 检查\进度跟踪\progress_scan.py --selftest
python 检查\引脚规划\pin_planner.py --selftest
```

命令行参数写错（拼错的开关、缺值的选项）会直接报错退出并列出可用参数，
不会像以前那样静默忽略、把"自检"跑成一次全量真实扫描。

GUI 路径（窗口构造、样式重刷、控件交互）自检覆盖不到，另留了一个 GUI 冒烟出口：
开主窗口 → 遍历侧栏/标签页 → 点一遍"不会弹对话框、不跑长任务"的按钮。正常跑完会打印
`GUI smoke 通过` 并退出；崩溃或卡死时进程不会正常收尾，所以**建议外面套一个超时**。

```
程序\嵌入式工具箱\build\release\Toolbox.exe --gui-smoke
程序\嵌入式工具箱\build\release\Toolbox.exe --selftest
程序\嵌入式工具箱\build\release\Toolbox.exe --gui-smoke --shot 图.png
```

加 `--shot 图片路径` 可顺便截图，并会打印窗口实际尺寸、屏幕可用区与"最小尺寸"
（排 UI 尺寸/布局问题用：窗口缩不小往往是某一页的最小尺寸把整摞顶住了）。
`本地工具/Git上传/` 的出口用法一致；STM32 速查的入口已收进 `Toolbox.exe`：
`--selftest` 会连着跑它的数据装载、条目计数与 28 例搜索基线，
`--search` / `--explain` / `--topics` / `--where` 也照旧可用（见下）。

```
Toolbox.exe --where                        # 速查数据位置与条目总数
Toolbox.exe --search [--sec ref|guide|build] [词...]
Toolbox.exe --explain [--sec ...] 词        # 打分明细
Toolbox.exe --topics                       # 主题归类逐条输出
```

## 约定

- 仓库根由脚本自适应向上查找（含 `.git` 或 `EnvMonitor` 的目录），因此工具箱整体
  挪到哪一层都能用；新增工程文件夹时无需改脚本。
- 程序定位自己的工具箱根目录：从 exe 所在目录向上找**同时含 `程序`、`检查`、`shared`**
  的那一层（以前用 `设计` 当标记，2026-10 去子程序后该目录已不存在）。
- 扫描排除：各脚本统一跳过 `本地工具`、`_参考实现备份`，以及 **`Linux-32`**（Linux + STM32
  自学试验场，工程由 EnvMonitor 复制而来、尚未改写，与 `.gitignore` 的"整体不入库"口径一致），
  不计入进度与检查统计。
- Qt 运行库已用 windeployqt 打包，双击 `打开工具箱.bat` 即可，本机无需另配环境。
- 重新构建（改了源码后）：跑 `python 构建.py`，只更新这一个程序。
  只清中间产物（保留 exe 与 DLL）：`python 构建.py --cleanonly`。

> 本目录属于"本地工具"，不入库。
