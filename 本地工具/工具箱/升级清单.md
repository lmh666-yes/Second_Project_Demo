## 本轮背景：能不能支持"除 F407 之外的绝大多数单片机"？

**结论：这一步还没走出来。** 2026-10-17 做了一次"F407 绑定审计"，把工具箱里**写死**的地方
逐条查出来了 —— 现在的工具箱是"**服务这个特定工程**（两块 F407 板 + StdPeriph 外设库 +
这套 E22 LoRa / W25QXX 缓存）的体检与生成器"，不是"任意单片机的通用工具"。审计结果：

| 写死的地方 | 位置 | 后果 |
|---|---|---|
| 引脚集合固定 `A~G × 0~F` | `检查/引脚规划/pin_planner.py:66` | F103（端口少）等芯片算不对空闲脚 |
| 工程/板路径固定两板 | 8 个检查器（`EnvMonitor\Project_1_检测端` / `Project_2_数据通信端`） | 换工程、换芯片直接"找不到工程" |
| 芯片资源上限固定 | `检查/编码守卫/encoding_guard.py:106`（512KB / 1024KB / 192KB RAM） | 换芯片占用百分比就算错 |
| 外设库固定 `stm32f4xx.h` + 寄存器写法 | `程序/工程模板/project_scaffold.py:58-73`、README 写"选 STM32F407Zx" | 生成物只对 F4 成立 |
| 只支持 F407ZE / F407ZG | `project_scaffold.py:52`、`--board` 参数 | 选不到 F103 |
| LoRa 波特率表内联 | `检查/LoRa检查/lora_check.py:69`（E22-400T22S） | 换 LoRa 模块就不适用 |

> 已做对的部分（可移植）：仓库根自适应、各脚本不写死盘符、检查器的外设/宏/RTC/引脚
> 大多**从工程头文件里读**，不是内置芯片手册。

**分三档走**（建议，别混在一起做）：
- **① 同系参数化**：STM32 家族（F1 / F4xx / L4 / H7…）—— 架构相同、寄存器模型相似，
  改的是参数与端口集合。**本轮可做，也最划算。**
- **② 跨库**：StdPeriph → HAL/LL —— 同一颗芯片但 API 完全不同，检查规则与生成器要换一套。
  **等手里真有 HAL 工程再做**（凭空写规则 = 内置印象数据，违反"只拦截+教方法"的红线）。
- **③ 跨架构**：51 单片机（8 位、SDCC、SFR、无 NVIC/DMA）—— 外设模型完全不同，
  等于把工具箱重写一遍；且 51 上的 FreeRTOS 移植本身是另一门学问。**暂不做**（清单 D 节注明）。

## A. 多芯片支持（① 同系参数化 —— 本轮可做）

- [ ] **A1 引脚端口集合改为动态解析** · 小 · `PORTS` 不再写死 `A~G`，改成"从工程头文件里实际出现的 `*_PORT` 宏"推出端口集合与位数——做完引脚规划立刻支持 F103（端口少）与 F4xx/H7（端口多），不靠内置芯片表
- [ ] **A2 检查器的"工程/板"可配置** · 中 · 8 个检查器不再写死 `Project_1_检测端` / `Project_2_数据通信端`：新增 `--project <工程目录>` 与多工程共用的"工程清单"，工具箱里用下拉选"我现在在做哪个工程"
- [ ] **A3 芯片资源上限参数化** · 小 · 编码守卫的 Flash/RAM 上限（512KB / 1024KB / 192KB）改为按芯片型号取（内置一张小表 + `--chip F103C8` 覆盖），Keil 日志缺失时照旧显式提示
- [ ] **A4 工程模板扩到 F103** · 大 · `--board` 从 F407ZE/ZG 扩到 F103C8/F103ZE 等：改 `stm32f4xx.h → stm32f10x.h`、时钟树与中断向量差异、寄存器风格按 F1 输出；README 里"用 Keil 选 STM32F407Zx"改为按所选芯片填
- [ ] **A5 LoRa 波特率表外置** · 小 · 把 E22-400T22S 的 AT+UART 支持列表挪到 `速查数据/rules/`（与 freertos_isr_rules.json 同口径），换模块只改数据文件、不改脚本
- [ ] **A6 工具箱加"当前工程/芯片"概念** · 中 · 设置页选"当前工程目录 + 芯片型号"，各检查器、体检面板、工程模板都跟着这个选择走（现在是把本仓库的两个工程写死在代码里）

## B. FreeRTOS 移植与骨架生成

- [ ] **B1 移植向导（产出配置，不只读配置）** · 大 · 现在 RTOS 生成页只做"读你已移植好的 `FreeRTOSConfig.h` → 生成 `main.c`"，只给一段"建议片段"。补一步：按芯片 + 任务清单**算出**一份 `FreeRTOSConfig.h`（各宏给值并附理由），并列出该放哪些 `port.c` / `portmacro.h`
- [ ] **B2 骨架生成支持任意工程的配置** · 小 · 现在能读用户指定的 config，但场景模板与自检写死了两个板子的路径；改成"配置来源可选（本仓库两板 / 自己指定）"
- [ ] **B3 移植自检** · 中 · 检查工程里 `FreeRTOSConfig.h` 与 port 文件是否齐全、`configPRIO_BITS` 与 NVIC 分组是否自洽、堆/栈是否够——即"移植这一步有没有漏"
