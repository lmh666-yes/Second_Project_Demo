**怎么用**：你要哪个升级，就在它前面的 `[ ]` 里填个 `x`（变成 `[x]`），保存后跟我说一声  
「按清单做」，我就只做打了勾的，没勾的不动。

- 这份清单**只列还没做的**；已完成的升级都记在 `升级进度.md`。

  自己临时想到的，写到 **G. 自定义升级** 那一节里，格式一样。

## A. 工程闭环（本轮重点，最值钱的一组）

- [x] **A1 阶段自动判定 + 回写进度文档** · 大 · 每个阶段给一组**可机器判**的验收条件  
  （文件在不在 / 关键 API 有没有被调用 / 检查器有没有严重项 / 板载自检是否 PASS），  
  跑一遍就把 `板N进度文档.md` 阶段总表的「状态 / 证据」填上，不用你手勾。  
  判不了的阶段（如"联调跑 30 分钟"）明确标「需人工确认」，不假装能判。  
  *验收：跑一次 `--stage-status`，板1 阶段 1~8 自动判定，阶段 9 标人工；连跑两次结果一致。*
- [x] **A2 一键 编译 → 烧录 → 板载自检 → 出结论** · 大 · 自动探测 `UV4.exe` / `STM32_Programmer_CLI.exe`  
  （像现在探测 Qt 那样），`UV4 -b` 编译 → 解析 `Objects\*.map` 拿体积 → 烧 hex →  
  开串口收板子的启动打印 → 按预期特征判 PASS/FAIL。失败时把编译错误行抓出来直接显示。  
  *验收：改坏一行代码 → 报"编译失败 + 错误行"；改好 → 报"编译 OK / 体积 / 烧录 OK / 自检 PASS"。*
- [x] **A3 体积与栈水位趋势** · 中 · 每次编译记 Flash / RAM / 各段体积 + 各任务栈水位，  
  存历史、画趋势；超预算或栈水位 < 20% 告警。把"哪次改动让体积涨了 2KB"变成可查。  
  *验收：连编两次出两个点；人为把栈改小 → 告警命中。*
- [x] **A4 阶段自检代码生成** · 大 · 按阶段生成 `selftest_stageN()`（如阶段 6 验组帧+CRC 回环、  
  阶段 7 验发一帧），塞进工程、串口回传 `STAGE6=PASS`，给 A1/A2 当判据。  
  *验收：生成的代码能编译；故意改坏 CRC → 串口回 `STAGE6=FAIL`。*
- [x] **A5 一键"板子当前状态快照"** · 小 · 编译 + 烧录 + 自检 + 截图 + 体积，打包成一个  
  `状态_日期/` 目录，出问题时连同现场一起留档。

## B. 全链路仿真（把"仿真"做成"数字孪生"）

- [x] **B1 全链路时序仿真 + SVG 时序图** · 大 · 一条命令跑完  
  板1 采集 → 换算 → 组帧 → LoRa（可设丢包/延迟/误码）→ 板2 转发 + 缓存 → 上位机解析 → 云，  
  出**一张 SVG 时序图**（每条消息一行、标时间与延迟），并断言：成帧数、丢包数、缓存条数、补传条数。  
  *验收：`--chain normal` 断言全通过；`--chain lossy --drop 20` 断言丢包数 = 20%±2、缓存条数对得上。*
- [x] **B2 故障剧本（断网 / 重启 / CRC 错）** · 中 · 预置几种剧本自动跑：  
  断网 30s 再恢复、板2 中途重启、CRC 错帧比例、队列塞满。  
  断言系统行为：**缓存不丢、补传不重复、上位机不崩**。  
  *验收：4 个剧本全过；把补传去重逻辑改坏 → 剧本报"重复补传 3 条"。*
- [x] **B3 上位机解析器对照** · 中 · 仿真产出的字节流直接喂给上位机的 `FrameParser`（编一个小 CLI），  
  断言"板1 组帧 → 上位机解出的物理量"逐字段一致。现在只对比了两板常量，没验过真解出来对不对。  
  *验收：字段全一致；把上位机 CRC 范围改错 → 对照报错并指出字段。*
