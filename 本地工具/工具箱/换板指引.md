# 换板指引：把工具箱改成"某块板的专属版本"

**一句话**：换板 = **复制一份板级配置改参数 + 指到新工程 + 重跑一遍自检**；
检查规则本身**不用改**（它们本来就是从工程的 `.h` 里读事实，不是内置芯片手册数据）。

> 现在工具箱服务的是 `EnvMonitor` 这套工程（板1 检测端 F407ZE / 板2 通信端 F407ZG）。
> 本页说明将来换别的板子时，怎么把它改成那块板的**专属版本**。做之前先读 `升级进度.md`
> 里"方向：以 F407 为主"那条，以及 `升级清单.md` E 节（哪些不做、为什么）。

---

## 一、要准备什么

| 需要 | 说明 |
|---|---|
| 新板的 Keil 工程 | 至少要有 `Project\` 下的 `FWLIB\inc`、`FWLIB\src`、`main.c`（检查器的"事实"全从这里读） |
| **原理图** | 工具**不替你看图**：引脚冲突、调试口占用、LoRa 接线这些，工具给候选与依据，你对着原理图确认 |
| 芯片参数 | 型号、Flash/RAM 容量（编码守卫要按它算占用百分比） |
| Python 3 | 跑检查用；双击 exe 不用装 Qt（Qt/MinGW 运行库已随 exe 打包） |

## 二、真正要改的只有三处

### ① 复制板级配置，改里面的参数（主要工作量）

把 `速查数据\rules\board_envmonitor.json` 复制成 `board_<新板名>.json`，逐项改：

| 字段 | 改成 |
|---|---|
| `boards[].name` | 新板名字（会出现在所有报告标题里） |
| `boards[].dir` | 新工程目录（相对仓库根，如 `EnvMonitor\Project_3_xxx\Project`） |
| `boards[].chip` / `flash_kb` / `ram_kb` | 芯片型号与容量（编码守卫用它算占用） |
| `boards[].ports` / `pins_per_port` | **该芯片实际有的端口集合**（如 F103 常见 `A~D`；引脚规划按它算空闲脚） |
| `boards[].debug_pins` | SWD/JTAG 口（F1/F4 都是 `PA13/PA14/PA15/PB3/PB4`；别的系列按手册核） |
| `boards[].keil_log` | Keil 复编日志文件名（放 `仓库巡检\验证日志\` 下；没有就留空，内存快照会显式提示缺） |
| `boards[].lora_header` / `lora_src` | LoRa 模块头文件与实现文件路径 |
| `extra.lora_bauds` | 你用的 LoRa 模块**实际支持**的波特率表（换模块时改这里，脚本不用动） |
| `extra.progress_docs` | 该工程自己的进度文档路径 |
| `extra.frame_constants_file` | 帧协议头文件（协议校验读它） |

> 表里每一条 = **一个要编译下载的工程**：引脚规划 / RTOS 检查 / LoRa 检查 / 协议校验
> 都按它逐项检查 —— 现在表里是板1、板2 和 **OTA 工程**（2026-10-17 补进去的，
> 之前 OTA 工程不在表里、这几个检查器根本没扫过它）。
> 例外：协议校验的"端到端回放"固定取前两块（板1 组帧 → 板2 解帧），
> 其余工程只统计、不参与两端对比。

### ② 让检查器读新配置

读取器是 `检查\boardcfg.py`：它去 `<仓库根>\本地工具\工具箱\速查数据\rules\` 下找
`board_envmonitor.json`。换板时把**文件名换成你那份**（改 `boardcfg.py` 顶部的默认文件名常量，
或直接把你的配置覆盖成 `board_envmonitor.json`）。

### ③ 生成类功能按新芯片调（这部分属"另一档"，见下）

`工程模板`（生成 STM32 骨架）与 `RTOS 骨架生成` 依赖芯片/外设库：现在只对 **F4 + 寄存器/StdPeriph 风格**成熟。
换到别的系列要改生成器模板（头文件名、时钟树、中断向量），属 `升级清单.md` 里 **② 跨库**那一档 ——
**等真有那套工程再做**。

## 三、天然可复用、**不用动**的部分

- 引脚口径：`*_PORT` / `*_PIN` 宏配对、冲突判定、调试口占用、"声明未用"判定
- 中断/优先级：`SYS_NVIC_SetPriority` 实际值、`FreeRTOSConfig.h` 里的上限与分组、配置漂移
- DMA 占用、编码/BOM/换行口径、断网缓存几何（读 `w25qxx_log.h` / `w25qxx.h`）
- 帧协议常量、字段偏移、命令字表与"应答位 = 请求 | 应答位"约定、两板端到端回放
- 进度扫描、链路仿真、LoRa 两板一致性

也就是说：**改了配置之后，8 个检查器的规则一条都不用改**（前提是新工程的头文件里确实写了那些宏）。

## 四、换装后怎么验证（4 步，都要过）

```
1) python 本地工具\工具箱\构建.py                     # 只在你改了 Qt 源码时
2) Toolbox.exe --selftest                             # 8 个检查器 + 工程模板生成器自检全 PASS
3) 逐个跑一次真实检查，看报告标题是不是新板名
   python 本地工具\工具箱\检查\引脚规划\pin_planner.py --quiet
4) Toolbox.exe --gui-smoke  /  --shot-overview        # 界面与面板仍正常
```

**关键确认**：报告里必须出现**新板名字**。若还是旧名字，说明配置没被读到 ——
`boardcfg.py` 读不到时会**回退到脚本内置的 F407 默认值**（不崩，但你会以为已经换好了）。
每个检查器的 `--selftest` 里都有"配置存在时两块板名字与 JSON 一致"的断言，跑一遍就能发现。

## 五、红线与边界（别越）

- **不内置芯片手册数据**：引脚复用表、外设-通道对照表必须对着数据手册/原理图核，工具只给依据与提醒。
- **51 单片机这类跨架构**：8 位、SDCC、SFR 直写、无 NVIC/DMA，外设模型完全不同 —— 等于重写工具箱，**当前不做**。
- **HAL/LL 工程**：等真有那套工程再做检查规则；没真工程只能凭印象编，正是上面那条红线。
