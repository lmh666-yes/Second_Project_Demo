# 环境监测系统
### STM32F407 双板 + LoRa + MQTT + Qt 上位机

> 两套独立固件（检测端 / 通信端）通过 LoRa 组网，通信端经 ESP8266 上云，
> PC 端用 Qt 实时显示曲线、告警与历史数据。

---

## 一、项目做什么

在实验室多点布置环境监测节点，自动采集温湿度、气压、光照、空气质量，数据经 LoRa 汇总到通信端，再经 WiFi/MQTT 上云，PC 上位机做实时可视化。

**解决的是"人工巡检抄表"的问题**：4 类参数自动采集、超限告警、历史可追溯。

## 四、通信协议：20 字节定长帧

```
┌──────┬──────┬──────┬────────────────────┬────────┬──────┐
│ AA55 │ CMD  │ LEN  │ 6 × int16 大端定点  │ CRC16  │ 55AA │
│ 2B   │ 1B   │ 1B   │ 12B                │ 2B     │ 2B   │
└──────┴──────┴──────┴────────────────────┴────────┴──────┘
```

| 字段 | 说明 |
|---|---|
| 帧头 | `0xAA55` |
| 命令 | `0x01` = 数据上报 |
| 长度 | `0x0C`（12 字节负载） |
| 数据 | 6 个 int16 大端：温度×100、湿度×100、气压×10、光照、TVOC、保留 |
| CRC16 | MODBUS 多项式，覆盖前 14 字节，**低字节在前** |
| 帧尾 | `0x55AA` |

下行指令：`0x20` 设采样周期、`0x22` 查状态、`0x24` 重启，应答字 = 命令 | `0x80`。

**CRC 校验独立复算**：另有独立校验程序计算 CRC，确认收发两端一致（不是"自己算自己"，而是双向验证）。

## 五、FreeRTOS 任务结构

检测端与通信端各 **6 个任务**：

| 任务 | 职责 |
|---|---|
| 采集 | 读 4 路 I2C 传感器 |
| 滤波 | 滑动滤波 + 双阈值迟滞（告警不抖） |
| 通信 | LoRa 收发 |
| 接收 | 下行指令解析 |
| 显示 | TFT 刷新 |
| 看门狗 | 喂狗 + 心跳检测 |

队列解耦各环节，**按栈水位实测调优**任务栈大小。

## 六、断网缓存（可靠性设计）

网络断开时数据不丢：

```
采样 → 带时间戳 → 写 W25Q128 环形日志（255 扇区 ≈ 1020KB ≈ 32640 条）
     → 网络恢复 → 按原时间戳自动补传（50ms/条）
```

- 环形覆盖：写满后从最旧开始覆盖
- 时间戳保留：补传时不是"现在的时间"，是采样的原始时刻
- 2 秒周期下 ≈ 18 小时缓存

## 十、关键设计点

### 1. 双阈值迟滞，告警不抖

单一阈值会让告警在临界值附近疯狂跳变。用「上阈值触发、下阈值恢复」的迟滞带，加滑动滤波，数据稳定。

### 2. 断网不丢数据

环形日志 + 原时间戳补传。这是这个项目最有价值的可靠性设计——**网络是不可靠的，但数据不能丢**。

### 3. 自检与验收

- Qt 上位机自检用例 18/18
- 量程校验 5/5
- 下发控制 22/22
- 端到端联调 rx=20 / bad=0 / pub=20 / fail=0 / lost=0

### 4. 双板分工清晰

检测端只做采集与上报，通信端只做汇聚与上云。**两块板可以独立编译、独立烧录、独立调试**。

## 十一、已知问题与改进方向

| 问题 | 现状 | 改进 |
|---|---|---|
| MQ-135 未接入 | 帧第 6 字段固定 0 | 硬件到手后接入 |
| 上位机与固件协议版本耦合 | 改帧格式要同步改两边 | 加协议版本字段 |
| TFT 刷新占用主循环 | 已用队列解耦 | 可用 DMA + 局部刷新 |
| 无 OTA | 需重新烧录 | 已有 OTA 救援脚本基础，可扩展 |

## 十二、这个项目解决了什么

不是"读几个传感器显示出来"，而是：

1. **两套独立固件**通过网络协同工作
2. **自定义二进制帧协议**（含 CRC 校验与双向验证）
3. **断网缓存 + 自动补传**（时间戳语义正确）
4. **FreeRTOS 多任务**（队列解耦、栈水位实测调优）
5. **Qt 上位机**（实时曲线、告警、CSV、命令下发）
6. **完整的自检与验收清单**（不是"能跑就行"）
