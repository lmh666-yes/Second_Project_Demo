# 环境监测系统
### STM32F407 双板 + LoRa + MQTT + Qt 上位机

> 两套独立固件（检测端 / 通信端）通过 LoRa 组网，通信端经 ESP8266 上云，
> PC 端用 Qt 实时显示曲线、告警与历史数据。

## 一、项目做什么

在实验室多点布置环境监测节点，自动采集温湿度、气压、光照、空气质量，数据经 LoRa 汇总到通信端，再经 WiFi/MQTT 上云，PC 上位机做实时可视化。

**要解决的问题**：替代人工巡检抄表——4 类参数自动采集、超限告警、历史可追溯。

## 四、通信协议：20 字节定长帧

```
┌──────┬──────┬──────┬────────────────────┬────────┬──────┐
│ AA55 │ CMD  │ LEN  │ 6 × int16 大端定点  │ CRC16  │ 55AA │
│ 2B   │ 1B   │ 1B   │ 12B                │ 2B     │ 2B   │
└──────┴──────┴──────┴────────────────────┴────────┴──────┘
```

| 字段 | 说明 |
|---|---|
| 帧头 | `0xAA55` |
| 命令 | `0x01` 环境帧上行；`0x10`–`0x16` 下行请求；`0x80`–`0xFF` 应答（= 请求 \| 0x80） |
| 长度 | `0x0C`（12 字节负载） |
| 数据 | 6 个 int16 大端：温度×100、湿度×100、气压×10、光照、TVOC、**第 6 字段保留（MQ-135 未接，固定 0）** |
| CRC16 | MODBUS 多项式，覆盖前 14 字节，**低字节在前** |
| 帧尾 | `0x55AA` |

**下行命令**：`0x16` 触发补传、`0x15` 回传历史帧（4 字节原始时间戳 + 20 字节原帧）、`0x96` 回报状态。应答字 = 命令 \| `0x80`。

**协议向量（自检用）**：
```
0x16 01 01 → AA 55 16 01 01 50 54 55 AA
0x16 01 00 → AA 55 16 01 00 91 94 55 AA
```

**CRC 双向验证**：板1 组帧、板2 解帧、Qt 再解一遍，三处独立计算 CRC 并互验。

## 六、断网缓存（可靠性设计）

网络断开时数据不丢：

```
采样 → 带时间戳 → 写 W25Q128 环形日志（255 扇区 ≈ 1020KB ≈ 32640 条）
     → 网络恢复 → 按原时间戳自动补传（50ms/条）
```

配置见 `w25qxx_log.h`：

```c
#define W25QXX_LOG_SECTORS   255U   /* ≈1020KB ≈ 32640 条，约 18 小时@0.5 帧/秒 */
#define W25QXX_LOG_SLOT_SIZE 32U    /* 32 字节/条，4KB 扇区正好 128 条 */
#define W25QXX_LOG_HDR_SIZE  12U    /* 12B 头 + 20B 整帧 */
```

- 环形覆盖：写满后从最旧开始覆盖
- 先写数据再写序号 → 掉电原子性
- 时间戳保留：补传的是采样原始时刻，不是当前时间

**已知不足**（设计文档自己列的）：
- 补传期间新帧只计数不补发
- 无掉电续传游标
- `0x96` 剩余条数只有 1 字节（255 表示"以上"）
- 清空 16 扇区期间挂起调度器 0.5~1 s

## 十一、这个项目真实的价值

不是"读几个传感器显示出来"，而是这几件**已经写进代码**的事：

1. **两套独立固件**通过网络协同，`SYS_TEST_BOARD` 宏分板、编译期断言防错
2. **自定义二进制帧协议**（20 字节定长 + CRC16 + 三端互验 + 协议向量自检）
3. **断网缓存 32640 条 + 原时间戳补传**（掉电原子性、环形覆盖）
4. **FreeRTOS 多任务**（队列解耦、栈水位实测调优、看门狗）
5. **Qt 上位机**（实时曲线、双阈值迟滞告警、CSV、补传控制）
6. **逐行代码取证的文档**（`实现事实清单.md` 572 行，每行结论都带文件行号）

**还没兑现的**：上板实测 + 自检接入 + MQ-135。

**这个项目最值钱的部分可能不是功能，是那份 `实现事实清单.md`**——把每一条结论都钉到具体文件的具体行，这种取证能力比"能跑"更难。
