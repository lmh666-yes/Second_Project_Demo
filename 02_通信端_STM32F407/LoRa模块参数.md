# 板 2（数据通信端）LoRa 模块参数记录

> 模块：亿佰特 **E22-400T22D**（433MHz，22dBm，UART）
> 规格书：[../项目外设资料/LoRa-E22/E22-400T22D 规格书.PDF](../项目外设资料/LoRa-E22/E22-400T22D%20规格书.PDF)
> 通用读取方法 / 寄存器位定义 / 两块比对：见 [../项目外设资料/LoRa-E22/模块参数记录.md](../项目外设资料/LoRa-E22/模块参数记录.md)

## 一、实测日期与方式

- 日期：**2026-10-22**
- 方式：CH340 USB-TTL + 串口助手，配置模式读取
- 模式：`M1 = 3.3V`（高）、`M0 = GND`（低）→ 模式 2 配置模式
- 串口：**9600 8N1**，HEX 发送 / HEX 显示
- 指令：`C1 00 09`（读寄存器，起始地址 0x00、长度 9）

## 二、原始回包

```
C1 00 09 00 00 00 62 00 17 03 00 00
└─ 应答 ─┘└─ 起始 ─┘└──────── 9 字节参数 ────────┘
```

连续读 4 次，回包完全一致，**与板 1 模块逐字节相同**。

## 三、参数解码

| 地址 | 值 | 含义 | 备注 |
|---|---|---|---|
| 00H | `00` | ADDH 地址高字节 | 地址 **0x0000** |
| 01H | `00` | ADDL 地址低字节 | |
| 02H | `00` | NETID 网络 ID | **0** |
| 03H | `62` | `011 000 010` | 串口 **9600 8N1**、空中速率 **2.4 kbps** |
| 04H | `00` | 分包 **240 字节**、RSSI 字节关、发射功率 **22 dBm** | 最大功率 |
| 05H | `17` = 23 | 信道 **CH=23** | **433.125 MHz**（410.125 + 23×1M） |
| 06H | `03` | 透明传输、无中继、无 LBT、WOR 接收方 | **透传模式** |
| 07H | `00` | CRYPT_H | 密钥 0 |
| 08H | `00` | CRYPT_L | **不加密** |

**判定：出厂默认值，未被修改过。**

## 四、与板 1 的比对（2026-10-22）

| 参数 | 板 2 | 板 1 | 是否一致 |
|---|---|---|---|
| 地址 | 0x0000 | 0x0000 | ✅ |
| NETID | 0 | 0 | ✅ |
| 串口/空速 | 9600 8N1 / 2.4k | 9600 8N1 / 2.4k | ✅ |
| 分包/功率 | 240B / 22dBm | 240B / 22dBm | ✅ |
| 信道 | 23 (433.125MHz) | 23 (433.125MHz) | ✅ |
| 工作模式 | 透明传输 | 透明传输 | ✅ |
| 加密 | 无 | 无 | ✅ |

**结论：两块模块 9 字节完全相同，无需修改任何参数，接上板子即可透传互通。**

互通要素：**同信道 + 同空中速率 + 同 NETID** 三者满足即可（透明传输模式下地址不参与过滤，出厂 `0x0000` 不影响）。

## 五、本板接线与软件对应关系

| 项 | 值 | 依据 |
|---|---|---|
| 串口号 | **USART6** | `FWLIB/inc/lora_e22.h` `SYS_LORA_UART = SYS_USART_6` |
| TX / RX 引脚 | **PC6 (TX) / PC7 (RX)** | 两板 `lora_e22.h` 仅此宏与 M0/M1/AUX 脚位不同，`lora_e22.c` 两板相同 |
| 波特率 | **9600 8N1** | 与模块 03H 一致 ✅ |
| M0 / M1 | **建议硬件直接接 GND**（透传） | 驱动中 M0/M1/AUX 宏当前被注释，不驱动；悬空会导致模式不定、收发随机失败 |
| AUX | 可悬空 | 未接时 `lora_wait_idle` 走 2ms 延时兜底 |
| 发射功率 | 22 dBm | 发射瞬时电流 **100~120 mA**，需确认 3.3V 轨余量 |

⚠️ **PC6/PC7 复用风险**：这组脚在部分 F407 开发板上与其他外设（晶振、以太网、LCD）有复用，上板前先确认板上丝印与实际连接，必要时用跳线接到备用 USART。

## 六、已知问题与注意事项

1. **供电**：板 2 同时挂 LoRa + W5500/ESP8266 等负载，发射峰值 120 mA 容易把 3.3V 拉垮。模块 VCC 就近并 **100 µF 电解 + 0.1 µF 陶瓷**。
2. **天线必须先接再上电**（不接天线发射会损伤功放）。
3. **驱动里的 AT 指令对本模块无效**：`lora_e22.h` 头部注明驱动是照 **E22-400T22S**（AT 固件）写的，`SendAT` / `ReadConfig` / `SetBaud` 在 **D 版（寄存器固件）** 上不可用。**透传收发不依赖这些函数，不受影响**。
4. **接收侧必须有人读取环形缓冲**：`SYS_USART_InitRxIT()` 开了接收中断，若 `vTaskLoraRx` 之类的任务不去把数据取走，缓冲会一直满，后续帧全部丢弃。

## 七、性能估算（基于 2.4 kbps 空速）

| 项目 | 数值 |
|---|---|
| 单帧 20 字节 + 前导/同步/包头/CRC ≈ 32 字节 = 256 bit | 空中时间 ≈ **107 ms** |
| 板 1 每 2 秒发一帧 | 占空比 ≈ **5%**，接收侧毫无压力 |
| 串口灌包 20 字节 @9600 | 21 ms |

**结论**：空中速率是瓶颈，若将来板 1 提到 1 秒多帧或增加 ACK 重传，需把两块模块 `03H` 的空中速率同步提高（4.8k / 9.6k / 19.2k）：

```
C0 03 01 32     ← 示例：9600 8N1 + 4.8k 空速（[2:0]=011）
```

⚠️ 写用 `C0`（掉电保存），不要用 `C2`（临时寄存器，掉电失效）。**两块必须同时改，否则立刻失联。**
