通用工具（查询软件、项目解析 App、工具箱、Git 上传）仍然在 `D:\GitHub_Project\本地工具\`，

## 一、诊断两块板

双击 `诊断/诊断两块板.bat`。默认采样 12 秒，加长：

```
诊断两块板.bat -Seconds 30
```

它同时打开电脑上所有串口，按内容识别：

- 出现 `TX_OK=` → 板1 检测端
- 出现 `rx=` → 板2 网关端

正常输出长这样：

```
板1 [COM9]  TX_OK 782 → 787   完整帧 2
板2 [COM10] rx 790 → 793  bad=0  cache=0/32640  net=1

结论：链路正常（板1 在发，板2 在收）
```

**判读表**

| 现象 | 说明 | 先查什么 |
|---|---|---|
| 板1 未识别 | 板1 没上电 / USB 没插 / 端口被串口助手占用 | 关掉串口助手 |
| 板1 有输出但 `TX_OK` 不涨 | MCU 被调试器 halt，或 LoRa 初始化失败 | 拔掉 J-Link 再按复位 |
| 板1 帧全是 0 | I2C 总线挂了（传感器全失败） | 断电 10 秒重启，看 `I2C1 scan: N dev` |
| 板2 `rx` 不涨 | 空口没通 | 板1 LoRa 的 M1 是否接地、板2 PC6/PC7 是否接反 |
| 板2 `bad` 涨 | 收到帧但解析失败 | 看帧是否 `AA 55` 开头 |
| 板2 `net=0` | WiFi/MQTT 没连上 | 热点是否 2.4G、SSID 密码、ESP 供电 |

> 注意：脚本打开串口时会拉 DTR/RTS，板2 如果没断开一键下载电路，会白屏几秒，属正常。

## 二、串口识别

```
powershell -File 诊断/串口识别.ps1
```

枚举所有 COM 各抓 3 秒，输出每个口是不是板1/板2、有没有数据。
板子换了 USB 口以后 COM 号会变，先用它确认。

## 三、长稳测试

双击 `长稳测试/长稳测试.bat`（默认 12 小时）。

- 每 10 秒记一行 CSV：`时间,板1_TX_OK,板1_TX_FAIL,板1_SHT30_FAIL,板2_rx,板2_bad,板2_pub,板2_fail,板2_cfail,板2_cache,板2_lost,板2_net`
- 结束时生成 `长稳_<时间>_汇总.txt`：丢包率、失败次数、重启次数
- 计数**变小**即判定重启

自定义时长：

```
powershell -File 长稳测试/长稳测试.ps1 -Hours 0.5
```

> 跑之前先确认端口号（用上面的串口识别）。

## 四、OTA 救援烧写

```
python OTA救援烧写.py COM7 固件.bin --ver 3
```

前提：Bootloader 已经进了救援态（串口在刷 `rescue mode: ...`）。

协议：`S` 写头 → `D` 逐包写入（带 CRC16-MODBUS）→ `E` 整片复验。
工具启动时自检 CRC 实现，正常输出 `CRC 自检 0x4B37 通过`。
