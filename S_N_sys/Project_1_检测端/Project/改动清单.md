# 改动清单 —— 库内"模式/选项一律用标准库宏名"清扫

> **日期** : 2026-09-22
> **工程** : `0001_标准模板库`（只改了本工程）
> **范围** : 整个模板库的注释/文档/示例 + 1 处等值调用；共 **约 85 处、28 个文件**
> **结果** : 编译 **0 Error / 0 Warning**（build_keil.bat 验证）

**规则（改写的依据）** :
凡是"**模式 / 选项 / 状态位 / 触发沿 / 上下拉 / 方向**"等可选择的值,文字里必须写
**标准库宏名**（一眼能对上 `stm32f4xx_xxx.h` 里的名字）,寄存器位编码只能跟在宏名后面作对照。

**例外（允许保持数字/编码,不改）** :
- **LED / KEY 的数字 id**（用户明确豁免）
- 设备固有值: LCD 命令码、器件寄存器码、滤波强度 0x0~0xF、波特率、周期数
- 返回码 0 / -1 / -2;极性开关 ACTIVE_LOW 0/1（无对应库宏）

## 四、移植到其他工程的方法

1. **本批改动里只有 1 处是代码,且数值等值**:`sys_dht11.c` 的 3 处 `GPIO_InInit(…, 1)` → `GPIO_InInit(…, GPIO_PuPd_UP)`。
   **其余全部是注释/文档**,照抄不会改变编译行为。
2. **推荐方式（不碰引脚配置）**:在目标工程里按 **第一节对照表** 逐项查找替换 → 再按 **第二节明细表** 逐文件核对 → 编译验证。
   （直接把本工程 `FWLIB` 整个覆盖过去也可行,但**注意目标工程"区块 1"的引脚/数量宏可能不同**,覆盖前先核对。）
3. 目标工程如果也有 `README.md` / `FreeRTOS` / `ETH` 目录,按 **第三节** 同步。
4. 改完编译验证标准:build_keil.bat → `0 Error(s), 0 Warning(s)`。
