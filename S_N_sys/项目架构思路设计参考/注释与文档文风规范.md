# 注释与文档文风规范

适用范围：两个固件工程（板1 / 板2）的 `FWLIB`、`main.c`、`README.md`，`S_N_sys/QT_project` 下的上位机源码与文档，以及"标准库速查"工具中的条目文本。

## 1. 注释写什么

按优先级写这四类内容，其他一律不写。

| 类型 | 写法 | 例 |
|---|---|---|
| 功能 | 一句话说明这个函数/宏/字段做什么 | `/* 设置 USART 的波特率，分频值按 PCLK 计算 */` |
| 约束 | 参数或返回值的取值范围、单位、合法组合 | `/* prescaler 取值 0~7，对应 1~8 分频 */` |
| 依据 | 为什么必须这样：手册规定、时序要求、硬件接线、协议约定 | `/* RM0090 第 30.6 节：清零 SR 后需再读 DR 才能清 ORE */` |
| 数值来源 | 超时、阈值、分频等数字的出处 | `/* 4 s 超时：板2 监控任务周期 1 s，取 4 个周期 */` |

不写：变更历史（放到 `改动清单.md`）、权衡讨论（放到设计文档）、个人评价。

## 2. 禁止出现的内容

本节是对后续所有文本与注释的长期要求：正文、表格、注释里一律不穿插表情符号或图标字符，只用纯文本；需要分点或标记对错时用文字，或用 `1) 2) 3)` 列表表达。

- 表情与图标字符：星号、对勾、叉号、警告三角、火焰、手指、灯泡、菱形等装饰性符号一律不写，也不写"注意！！！"这类强调。
- 修辞与情绪：值得称赞、亮点、很稳、非常关键、极其重要、坑、踩雷、名不副实、说白了、一句话、顺手、顺便、恰恰、反过来、其实。
- 反问句与感叹号：`为什么？`、`这就会出问题！`。
- 自评与他评：`这里处理得很干净`、`设计得好`。
- 第二人称说教：`你会发现`、`你可能想问`、`记住`、`务必`、`千万别`。
- 面试/演示话术：面试、加分项、答辩、演示话术、亮点。技术文档只陈述事实。
- 破折号连续使用（`——` 一段里出现两次以上）与括号内吐槽。

## 3. 句子要求

- 陈述句，短句。一句话一个意思。
- 术语用工程通用说法：使能、失能、去抖、重同步、忙等、临界区、抢占。
- 需要分点时用 `1) 2) 3)`，不用 emoji 或符号列表。
- 注释块（`/* ... */`）一般不超过 4 行；需要更长的说明时，写进对应的设计文档并在注释里指明文档名。
- 只保留与代码直接相关的技术信息，删除解释性铺陈。

## 4. 不改动的内容

- 代码逻辑、宏名、类型名、函数签名、数值、位域、寄存器名。
- 编译开关、宏定义取值、字符串常量中用于协议/日志的关键字（如 `OK`、`ERROR`、`PASS`）。
- 文件编码：`main.c` 为 GBK(936)，`FWLIB` 下的 `.c/.h` 与 Qt 源码为 UTF-8，不得改变。
- 换行风格（LF）与缩进。

## 5. 命名规范

- 函数用"动词 + 对象"：`SYS_FRAME_Send`、`W25QXX_LogWrite`、`SYS_USART_InitRxIT`。
- 避免叙事式长名（如 `checkThenDoXxx`、`handleAndStoreFrame`）；一个名字只表达一个动作。
- 静态量用 `s_` 前缀，全局量用 `g_` 前缀，宏全大写。
- 重命名必须同步全部引用点，并以复编通过为准。

## 6. 文档要求

- 设计文档写"怎么做"与"为什么这样定"，不写工作过程与心路。
- 每条参数、时序、地址都要能追到出处（手册章节、器件型号、代码文件与行）。
- 未验证的内容必须标注"未验证"，并写清验证方法。
