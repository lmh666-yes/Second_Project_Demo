# 程序模块与改动清单

日期：2026-10-11　　工程：`S_N_sys\Project_1_检测端`、`S_N_sys\Project_2_数据通信端`

本文件回答两个问题：两块板的程序模块搭建到底动了哪些文件；后续能不能只写一个新的 `main.c` 就用起来。文中数字均为实测：`.uvprojx` 里的文件列表、`git diff`、`本地工具\仓库巡检\改动分类.py`。

## 1. 一个工程由哪几部分组成

两个工程的结构相同，都是"一个 `main.c` + 一套驱动库 + FreeRTOS + 以太网库 + 芯片支持文件"：

| 目录 | 来源 | 内容 |
|---|---|---|
| `Project\main.c` | 本项目 | 唯一一个应用文件，任务与业务全部在这里 |
| `Project\FWLIB\inc`、`src` | 本项目驱动库 | 板级与器件驱动（串口、SPI、I2C、RTC、看门狗、LoRa、Flash 等） |
| `Project\FreeRTOS\src`、`inc`、`port` | 第三方 + 移植层 | 内核源码、`FreeRTOSConfig.h`、`heap_4.c`、`port.c`、`freertos_hooks.c` |
| `Project\ETH\src`、`inc`、`port` | 第三方（ST） | `stm32f4x7_eth.c` 等，两工程都参与编译但默认不启用 |
| `Project\RTE`、`Objects`、`Listings` | Keil 生成 | 启动文件、`system_stm32f4xx.c`、编译产物 |

Keil 工程文件：板1 是 `Project\标准模板.uvprojx`，板2 是 `Project\000标准模板库.uvprojx`。

## 4. 后续新建一个 main.c 的做法

可以用模板工程派生新工程，但要注意拷贝范围与宏：

1. 整套拷贝工程目录（`Project` 整个目录），不要只拷 `main.c`：驱动库、FreeRTOS、Keil 工程文件都要一起走。
2. 在 Keil 的 C/C++ 选项里改 `<Define>` 的 `SYS_TEST_BOARD`（1 = 检测端，2 = 数据通信端），板卡型号宏 `STM32F40_41xxx` 保持不变。
3. 新 `main.c` 保留三件事：`SYS_NVIC_Init()` 放在第一句；`GPIO_ClaimDump()` 放在调度器启动前；`SYS_WDG_Init()` 与每个任务的心跳上报成对出现。
4. 若新工程要用模板库里没参与编译的驱动，在 Keil 的 FWLIB 分组里 Add Existing Files 加入对应 `.c`，并把新目录加进 IncludePath。
5. 编码与换行：`main.c` 是 GBK(936) + LF，`.uvprojx` 也是 GBK；用 UTF-8 编辑器保存会乱码。

两套驱动库的命名不完全一致，选模板时要注意：

- 板1 库带 `sys_` 前缀的器件文件：`sys_dht11.c`、`sys_modbus.c`、`sys_oled.c`、`sys_mpu6050.c`；
- 板2 库对应的是裸名文件：`dht11.c`、`modbus.c`、`oled.c`、`mpu6050.c`，另有 `w25qxx.c`、`w25qxx_log.c`、`at24c02.c`、`mqtt.c`、`esp8266.c`、`sys_can.c`、`sram.c` 等板1 库里没有的。
- 新 `main.c` 的 include 必须与所选那套库的文件名一致。
