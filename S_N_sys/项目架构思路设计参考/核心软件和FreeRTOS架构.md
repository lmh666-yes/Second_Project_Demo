【板子2：边缘网关 (Gateway)】 —— 汇聚数据，双路转发（PC 端 + 云端）

                                      │ (USART6 PC6/PC7, 9600)
                                      ▼

   │           找帧头 0xAA55 → 验长度 0x0C → CRC16 → 验帧尾 0x55AA          │
   │           校验失败：丢一个字节重新找帧头（不要整包丢弃）                 │

                                      │
                                      ▼
                              [USB 转 TTL / RS232 到 PC]
                                      │

【底层系统支撑】 —— 支撑上述任务运行的基础
================================================================================================
   ┌───────────────────────────────────────────────────────────────────────┐
   │ 【任务8】MonitorTask (监控任务) - 优先级 5（最高）                     │
   │ 运行机制：直接用工程已有的 `sys_wdg` 心跳汇总接口，不用自己写位图        │
   │   · 配置一次：把 FWLIB/inc/sys_wdg.h 里的                              │
   │       SYS_WDG_HEARTBEAT_COUNT 从默认 0 改成实际参与的任务数             │
   │       （板1 = 3，板2 = 4）                                            │
   │   · 每个任务跑完一轮就报到：                                           │
   │       板1  SensorTask  → SYS_WDG_Heartbeat(0)                         │
   │            ProcessTask → SYS_WDG_Heartbeat(1)                         │
   │            CommTask    → SYS_WDG_Heartbeat(2)                         │
   │       板2  CommRxTask  → SYS_WDG_Heartbeat(0)                         │
   │            ForwardTask → SYS_WDG_Heartbeat(1)                         │
   │            CloudTask   → SYS_WDG_Heartbeat(2)                         │
   │            CacheTask   → SYS_WDG_Heartbeat(3)                         │
   │   · MonitorTask 里只调 SYS_WDG_HeartbeatPoll()：全员到齐才喂狗          │
   │     不能只判断"MonitorTask 自己还在跑"——否则某个任务死循环时            │
   │     看门狗照样被喂，故障被完全掩盖                                      │
   │     （库注释原话："还照常喂狗，看门狗就失去意义了（心跳汇总就是治这个的）"）│
   │   · 事件驱动任务（Forward/Cloud/Cache）额外用 `sys_softimer` 兜底：     │
   │       SYS_SOFTIMER_Add(cb, N*1000) —— 超过 N 秒没被唤醒也算异常         │
   │   · 复位原因诊断：SYS_WDG_ResetCauseDecode() 可判断这次是不是被看门狗    │
   │       复位（SYS_WDG_RST_IWDG / SYS_WDG_RST_WWDG / RST_POR / RST_BOR…） │
   ├───────────────────────────────────────────────────────────────────────┤
   │ 【故障诊断】sys_fault —— CPU 故障"黑匣子"（建议一开始就挂上）           │
   │   · SYS_FAULT_Init() 在 main 开头调用一次                              │
   │   · 接管 NMI / HardFault / MemManage / BusFault / UsageFault，          │
   │     把出错地址、寄存器、故障状态存进全局 SYS_FAULT_Record               │
   │   · SYS_FAULT_SetCallback(OnFault) 可在故障瞬间先报警（翻 LED/发串口）， │
   │     SYS_FAULT_Report() 事后格式化输出                                  │
   │   · 与 FreeRTOS 共存：不碰 SVC / PendSV / SysTick（那些归 RTOS 管）     │
   │   · 价值：野指针 / 数组越界 / 栈溢出时，板子不再是"突然卡死零提示"        │
   │   回调运行在异常上下文，只能做最简单的事（轮询串口发几十字符、翻 LED）， │
   │      不要调延时函数、不要再开中断、不要调 RTOS API                       │
   ├───────────────────────────────────────────────────────────────────────┤
   │ 【互斥锁 Mutex】保护共享资源                                            │
   │   · 板1：I2C 总线（SHT30 / BMP280 / BH1750 / CCS811 共用一条总线）      │
   │   · 板2：无（LoRa/Qt/ESP8266 各占一路独立串口，W25Q 只被 CacheTask 用）  │
   │   · 串口打印（USART1 调试口）若多任务共用也需加锁                        │
   │ 原因：防止多个任务同时访问同一硬件导致数据错乱 + 优先级反转              │
   ├───────────────────────────────────────────────────────────────────────┤
   │ 【任务9】Idle Task (空闲任务) - 优先级 0（系统自动创建）                 │
   │ 运行机制：常规空闲任务。本工程不启用 Tickless 低功耗                   │
   │   （configUSE_TICKLESS_IDLE = 0；设备为 USB 供电固定式，无常驻电池需求） │
   └───────────────────────────────────────────────────────────────────────┘

【工程实际的 FreeRTOS 配置】（据 FreeRTOS/port/FreeRTOSConfig.h 实测）
================================================================================================
   configUSE_PREEMPTION                        1        抢占式调度
   configUSE_TICKLESS_IDLE                     0        未启用低功耗
   configCPU_CLOCK_HZ                          168 MHz
   configTICK_RATE_HZ                          1000     1 ms 一个 tick
   configMAX_PRIORITIES                        8        可用优先级 0~7
   configMINIMAL_STACK_SIZE                    128      字
   configTOTAL_HEAP_SIZE                       30 KB    heap_4；注意余量
   configUSE_MUTEXES                           1
   configUSE_TIMERS                            1
   configSUPPORT_STATIC_ALLOCATION             0        只支持动态分配
   configCHECK_FOR_STACK_OVERFLOW              2
   configUSE_MALLOC_FAILED_HOOK                1
   configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY 5       中断优先级红线

   三条必须遵守的约束
   1. 抢占优先级数值 ≥ 5 的中断里，才能调用以 FromISR 结尾的 FreeRTOS API；
      库里默认 SYS_USART_IRQ_PRE_PRIO = 2（比 5 更"高"）→ 用默认值就不能在
      串口 ISR 里直接调 FreeRTOS API，必须把该中断的抢占优先级改到 5 或更低。
   2. NVIC 优先级分组要用 NVIC_PriorityGroup_4（4 位全给抢占优先级），
      否则 configASSERT 里对优先级的断言会失败。
   3. 上了 RTOS 之后不要调用 SYS_CLK_Switch 切低频档——configCPU_CLOCK_HZ 是
      编译期常量，运行时切频会导致 tick 周期与延时全部算错。

【所用 API 风格】
   本工程直接使用原生 FreeRTOS API（vTaskDelayUntil / xSemaphoreGiveFromISR /
   xQueueSend ...），不使用 CMSIS-RTOS 封装层。
   实测：工程内不存在 cmsis_os.h / cmsis_os.c；osDelayUntil/osSemaphoreRelease 全仓库 0 命中。
   写代码时不要照着 STM32 官方例程抄 osXxx，会编译不过。
