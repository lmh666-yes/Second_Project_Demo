# 精密仪器实验室环境监护系统

基于两块 STM32F407 开发板的分布式环境监测系统（综合设计项目）。

采集节点负责环境数据采集（温湿度、气压、光照、空气质量），经 LoRa 无线发送；边缘网关汇聚数据后转发至 Qt 上位机，并通过 ESP8266 + MQTT 上报巴法云。下位机基于 ST 标准外设库与 FreeRTOS（任务、队列、信号量）开发。

> 仓库根目录下只有 `S_N_sys/` 一个目录（外加 `.gitignore`），本文件位于其中的 `S_N_sys/项目架构思路设计参考/`。下面提到的路径都从仓库根目录写起；`项目进度.md`、`上板验证步骤.md`、`代码审查报告.md` 与本文件同目录。

> 进度跟踪与当前现状见 `项目进度.md`；逐条验收步骤见 `上板验证步骤.md`；历史代码审查结论见 `代码审查报告.md`。

## 系统构成

| 角色 | 硬件 | 软件 | 工程入口 |
|---|---|---|---|
| 采集节点（板1） | STM32F407ZE（GEC-M4） | 标准外设库 + FreeRTOS，4 个任务 | `S_N_sys/Project_1_检测端/Project/标准模板.uvprojx` |
| 边缘网关（板2） | STM32F407ZG（普中-天马 F407） | 标准外设库 + FreeRTOS，5 个任务 | `S_N_sys/Project_2_数据通信端/Project/000标准模板库.uvprojx` |
| 上位机 | PC | Qt 5（qmake + MinGW） | `S_N_sys/QT_project/SerialMonitor/SerialMonitor.pro` |
| 云端 | 巴法云 | ESP8266 AT + MQTT | 板2 经 USART3 上行 |

数据链路：板1 采集 → 20 字节定长帧 → LoRa E22（433 MHz，9600）→ 板2 校验入库 → USART2（经 P6 跳线选 SP3232）→ USB-TTL → Qt 上位机；板2 另经 ESP8266 向巴法云上报。

## 通信协议要点

| 项 | 约定 |
|---|---|
| 帧格式 | `AA 55` + 命令 + 长度 + 数据 + CRC16-MODBUS + `55 AA`，共 20 字节（环境帧） |
| 命令分区 | `0x01` 环境帧上行；`0x10`~`0x16` 下行请求；`0x80`~`0xFF` 应答（应答 = 请求 \| 0x80） |
| 补传通路 | `0x16` 触发补传，`0x15` 回传历史帧（4 字节原始时间戳 + 20 字节原帧），`0x96` 回报进度 |
| 断网缓存 | W25Q128 专用 64 KB：16 扇区 × 128 槽 × 32 字节，共 2048 条；槽 = 序号 4 + 时间戳 4 + 长度 2 + CRC16 2 + 数据 20 |
| 三端一致 | 同一套帧格式在板1 组帧、板2 解帧、Qt 再解一遍，两端都有自检用例钉住 |

## 编译与验证

```powershell
# 两板 Keil 复编 + Qt 构建与三项自检 + 文风检查
powershell -ExecutionPolicy Bypass -File 本地工具\仓库巡检\最终验证.ps1

# 只跑 Qt 侧（-SkipKeil 跳过 Keil，-SkipStyle 跳过文风检查）
powershell -ExecutionPolicy Bypass -File 本地工具\仓库巡检\最终验证.ps1 -SkipKeil -SkipStyle
```

两个 Keil 工程需在 `Options for Target -> C/C++ -> Define` 里带 `SYS_TEST_BOARD=1`（板1）或 `=2`（板2），漏填会编译报错提示。

巡检与辅助脚本（均在 `本地工具/仓库巡检/`）：`project_check.ps1` 生成内容检查报告，`pin_audit.py` 扫描引脚冲突，`改动分类.py` 区分代码改动与注释改动，`文风检查.ps1` 统计说明文字的 AI 腔特征。

> 这些脚本放在开发机的 `本地工具/` 下，不随仓库上传（仓库里只有 `S_N_sys/` 的源码与文档）；换一台机器要跑验证，得把 `本地工具/` 一起拷过去。
