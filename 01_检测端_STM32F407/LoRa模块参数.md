# 板 1（检测端）LoRa 模块参数记录

> 模块：亿佰特 **E22-400T22D**（433MHz，22dBm，UART）
> 规格书：[../项目外设资料/LoRa-E22/E22-400T22D 规格书.PDF](../项目外设资料/LoRa-E22/E22-400T22D%20规格书.PDF)
> 通用读取方法 / 寄存器位定义 / 两块比对：见 [../项目外设资料/LoRa-E22/模块参数记录.md](../项目外设资料/LoRa-E22/模块参数记录.md)

## 一、实测日期与方式

- 日期：**2026-10-22**
- 方式：CH340 USB-TTL + 串口助手，配置模式读取
- 模式：`M1 = 3.3V`（高）、`M0 = GND`（低）→ 模式 2 配置模式
- 串口：**9600 8N1**，HEX 发送 / HEX 显示
- 指令：`C1 00 09`（读寄存器，起始地址 0x00、长度 9）

## 二、原始回包

```
C1 00 09 00 00 00 62 00 17 03 00 00
└─ 应答 ─┘└─ 起始 ─┘└──────── 9 字节参数 ────────┘
```

连续读 4 次，回包完全一致，无抖动。

## 三、参数解码

| 地址 | 值 | 含义 | 备注 |
|---|---|---|---|
| 00H | `00` | ADDH 地址高字节 | 地址 **0x0000** |
| 01H | `00` | ADDL 地址低字节 | |
| 02H | `00` | NETID 网络 ID | **0** |
| 03H | `62` | `011 000 010` | 串口 **9600 8N1**、空中速率 **2.4 kbps** |
| 04H | `00` | 分包 **240 字节**、RSSI 字节关、发射功率 **22 dBm** | 最大功率 |
| 05H | `17` = 23 | 信道 **CH=23** | **433.125 MHz**（410.125 + 23×1M） |
| 06H | `03` | 透明传输、无中继、无 LBT、WOR 接收方 | **透传模式** |
| 07H | `00` | CRYPT_H | 密钥 0 |
| 08H | `00` | CRYPT_L | **不加密** |

**判定：出厂默认值，未被修改过。**

## 六、已知问题与注意事项

1. **供电塌陷（未解决）**：接上模块 VCC 后板子串口无输出，取掉 VCC 即恢复。判断为 3.3V 轨被发射峰值电流拉垮 → 建议模块 VCC 就近并 **100 µF 电解 + 0.1 µF 陶瓷**，或改用 DC 供电。
2. **`main.c:476` 发送判断反了**：`LORA_E22_WaitReady()` 返回 `1=空闲 / 0=忙`，代码却与 `LORA_E22_OK(0)` 比较，导致每帧都打印「AUX 一直忙，本帧放弃」，一帧都发不出去。修法：改成 `if (LORA_E22_WaitReady(...) != 0U)` 或 `if (!LORA_E22_IsBusy())`。
3. **驱动里的 AT 指令对本模块无效**：`lora_e22.h:5-6` 注明驱动是照 **E22-400T22S**（AT 固件）写的，`SendAT` / `ReadConfig` / `SetBaud` 在实际的 **D 版（寄存器固件）** 上不可用。**透传收发不依赖这些函数，不受影响**；但不要用 `ReadConfig()` 的返回值判断模块好坏。
4. **天线必须先接再上电**（规格书：不接天线发射会损伤功放）。

## 七、性能估算（基于 2.4 kbps 空速）

| 项目 | 数值 |
|---|---|
| 20 字节帧 + 前导/同步/包头/CRC ≈ 32 字节 = 256 bit | 空中时间 ≈ **107 ms** |
| 2 秒一帧（当前代码） | 占空比 ≈ **5%** |
| 1 秒一帧 | 占空比 ≈ **11%** |
| 串口灌包 20 字节 @9600 | 21 ms |

**结论：串口比空中快 4 倍，连续发送必须等 AUX 空闲，否则模块丢包。**

若需提速（提高刷新率 / 加 ACK），把两块模块的 `03H` 空中速率改为 4.8k / 9.6k / 19.2k：

```
C0 03 01 32     ← 示例：9600 8N1 + 4.8k 空速（[2:0]=011）
```

⚠️ 写用 `C0`（掉电保存），不要用 `C2`（临时寄存器，掉电失效）。**两块必须同时改。**
