# 改动清单 —— 库内"模式/选项一律用标准库宏名"清扫

> 日期 : 2026-09-22
> 工程 : `0001_标准模板库`（只改本工程）
> 范围 : 整个模板库的注释/文档/示例，另有 1 处等值调用；共约 85 处、28 个文件
> 结果 : 编译 0 Error / 0 Warning（build_keil.bat 验证）

规则（改写依据）：
凡"模式 / 选项 / 状态位 / 触发沿 / 上下拉 / 方向"这类可选择的值，文字中必须写标准库宏名（与 `stm32f4xx_xxx.h` 中的名字一致），寄存器位编码只能跟在宏名后作对照。

例外（保留数字/编码，不改）：
- LED / KEY 的数字 id（用户明确豁免）
- 设备固有值：LCD 命令码、器件寄存器码、滤波强度 0x0~0xF、波特率、周期数
- 返回码 0 / -1 / -2；极性开关 ACTIVE_LOW 0/1（无对应库宏）

## 四、移植到其他工程的方法

1. 本批改动里只有 1 处是代码，且数值等值：`sys_dht11.c` 的 3 处 `GPIO_InInit(…, 1)` → `GPIO_InInit(…, GPIO_PuPd_UP)`。其余全部是注释/文档，照抄不会改变编译行为。
2. 做法（不改引脚配置）：在目标工程里按第一节对照表逐项查找替换 → 再按第二节明细表逐文件核对 → 编译验证。
   （直接把本工程 `FWLIB` 整个覆盖过去也可行，但目标工程"区块 1"的引脚/数量宏可能不同，覆盖前先核对。）
3. 目标工程如果也有 `README.md` / `FreeRTOS` / `ETH` 目录，按第三节同步。
4. 编译验证标准：build_keil.bat → `0 Error(s), 0 Warning(s)`。

## 附录六：帧协议定稿（2026-10-10，`sys_frame` 改造）

> 背景：附录三那次只加了 `Build`/`Verify` 两个助手，帧格式本身仍是单字节 `AA`…`55` 加逐字节异或，并靠 `SYS_FRAME_WITH_LEN` 在"带长度/简化帧"两种格式间切换;而项目定稿的是双字节帧头 + CRC16-MODBUS 的 20 字节环境帧，两者不匹配，需要改造帧格式而不是改一个宏。
> 本次把 `sys_frame` 从上层 API 到底层帧格式一次改到位，并删除格式切换开关（只留一种格式，减少一种出错可能）。两板 `sys_frame.c/.h` 由构造保证同源（逐字节相同）。

| 项目 | 内容 |
|---|---|
| 线上格式 | `AA 55 \| CMD \| LEN \| DATA \| CRC16低 CRC16高 \| 55 AA`;总长 `8 + LEN`;`LEN` 上限 `SYS_FRAME_MAX_PAYLOAD` = 64（最大帧 72 字节） |
| 校验 | CRC16-MODBUS（初值 `0xFFFF`、多项式 `0x8005` 反射为 `0xA001`、末不异或）;范围 = 帧内 `[2 .. 4+LEN)`，即 CMD + LEN + DATA，不含帧头、不含帧尾、不含 CRC 自身。附带性质：把 CRC 两字节也算进去结果为 0 |
| 新增宏 | `SYS_FRAME_HEAD_HI/LO` = `0xAAU`/`0x55U`;`SYS_FRAME_TAIL_HI/LO` = `0x55U`/`0xAAU`（帧尾与帧头相反）;`SYS_FRAME_OVERHEAD` = `8U` |
| 删除宏 | `SYS_FRAME_HEAD`、`SYS_FRAME_TAIL`、`SYS_FRAME_WITH_LEN`，连同全部"简化帧"代码路径;`SYS_FRAME_SendShort` 现语义 = CMD + 空数据段（8 字节整帧），不再是原来的 4 字节简化帧 |
| 错误码改名 | `SYS_FRAME_ERR_CHECK(4U)` → `SYS_FRAME_ERR_CRC(4U)`（数值不变）;旧名保留为别名 `#define SYS_FRAME_ERR_CHECK SYS_FRAME_ERR_CRC`，老代码不用改 |
| 新增助手 | `SYS_FRAME_BuildEnv(out, cap, temp_x100, humi_x100, press_x10, light, tvoc, mq135)` 返回 20 / 0;`SYS_FRAME_UnpackEnv(payload, len, …)` 拆数据段（不是整帧），返回 `SYS_FRAME_OK` / `SYS_FRAME_ERR_PARAM` |
| 环境帧字段 | `CMD = SYS_FRAME_CMD_ENV 0x01U`、`LEN = SYS_FRAME_ENV_LEN 0x0CU`;数据段偏移 `TEMP` 0 / `HUMI` 2 / `PRESS` 4 / `LIGHT` 6 / `TVOC` 8 / `MQ135` 10（对应整帧内 4/6/8/10/12/14，CRC 在 16/17，帧尾 18/19，整帧 20）;全部大端;`PRESS` 是 hPa × 10 而非 ×100（×100 时 1013.25 hPa → 101325 会溢出 uint16） |
| 数据段自由度 | 数据段可以出现 `0xAA` / `0x55`。本格式靠"长度 + CRC16"定界，不要求数据避开帧头帧尾 |
| 解析要求 | 帧尾 `0x55AA` 与下一帧帧头 `0xAA55` 相邻会拼出 `… 55 AA AA 55 …`，因此不能见到 `0xAA55` 就当帧头;必须 1) 连续两字节帧头 + 2) 长度自洽（`LEN + 8 == 实际帧长`）+ 3) 从 CMD 起重算 CRC16 相等，三重确认（`SYS_FRAME_Verify()` 一次查全） |
| 未变项 | 公共 API 签名全部不变（`Send/SendShort/Poll/Available/Get/Feed/Reset/ErrCount` + 5 个 `*Legacy` + `Build`/`Verify`）;按 uart 实例化状态机（`fx[SYS_USART_COUNT]`）、只保留最新一帧、`Get` 的 `cap` 越界检查（不足返回 2 且不清 ready）均保留 |
| 两板差异 | `sys_frame.c` 524 行、`sys_frame.h` 277 行，两板逐字节相同（MD5 `1B92F37DBF598A9B191CDB2E198FC43F` / `4BB8CE17075DDD92BD6547B75ECA29CC`）。不再依赖任一板的 modbus 模块：文件内自带 `static uint16_t frame_crc16()` / `frame_crc16_update()`（注释说明"故意与 modbus 模块重复，以保持本文件两板同源"），已比对与 `SYS_MODBUS_Crc16` / `MODBUS_CRC16` 完全等价 |
| 调用者 | 全仓库 `.c/.h` 中除自身外无人使用 `SYS_FRAME_*`，因此删宏 / 改名 / 换格式未破坏任何调用者。两个 `main.c` 用的是自己那套 `FRAME_*` 宏 + 各自的 modbus CRC，与本模块无耦合 |
| 编译验证 | 两板均 `0 Error(s), 0 Warning(s)`、UV4 退出码 0;板1 `Code=27004 RO-data=1496 RW-data=296 ZI-data=32928`、板2 `Code=33288 RO-data=2236 RW-data=356 ZI-data=33572` |
